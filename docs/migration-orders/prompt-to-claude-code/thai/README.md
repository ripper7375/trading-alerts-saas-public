ไฟล์ `SESSION-WALKTHROUGHS.md` ถูกสร้างขึ้นและนำไปวางไว้ในโฟลเดอร์ `prompt-to-claude-code/` ของคุณ คู่กับไฟล์คำสั่ง (prompt) อีก 3 ไฟล์

ไฟล์นี้จะช่วยสอนคุณผ่านการจำลองบทสนทนาแบบสมบูรณ์ แทนที่จะใช้ตัวย่อให้งง สิ่งที่ทำให้งานนี้ง่ายขึ้นคือ: การทำงานทั้งหมดราวๆ 60 รอบ (sessions) สามารถจัดกลุ่มออกมาได้เป็นแค่ 7 รูปแบบหลักๆ ดังนั้นในไฟล์นี้จึงมีบทสนทนาตัวอย่าง 7 ชุด พร้อมกับตารางที่บอกว่าคุณควรใช้วิธีพูดแบบไหนในรอบไหน

ไฟล์จะเริ่มต้นด้วย "จังหวะการทำงาน" (The rhythm) — ซึ่งมี 5 ขั้นตอนที่คุณจะต้องทำซ้ำในทุกๆ รอบ (Advisor ร่างแผน → คุณอนุมัติ → สั่งเริ่มงาน → ระบบทำงาน → สั่งปิดงาน) พร้อมการประเมินเวลาให้เห็นว่า คุณจะใช้เวลาที่ต้องสั่งงานด้วยตัวเองจริงๆ แค่ประมาณ 20–30 นาทีต่อรอบเท่านั้น

ต่อมาคือส่วนของการจำลองสถานการณ์ (Walkthroughs) ซึ่งจะแสดงให้เห็นชัดๆ ว่าคุณต้องก๊อปปี้อะไรไปแปะ, การตอบกลับที่ถูกต้องของระบบหน้าตาเป็นอย่างไร, และอะไรคือสัญญาณเตือนภัย (Red flags) ที่หมายความว่า "อย่าเพิ่งสั่งให้เริ่มงาน (Go)":

- A — การเริ่มต้นระบบครั้งแรก (0-1 bootstrap) แบบทีละเทิร์น รวมไปถึงสถานการณ์จำลองที่คุณต้องตัดสินใจ (เช่น จะทำยังไงถ้าหาโหลดเวอร์ชันที่ต้องการไม่ได้)
- B — การทำงานรอบปกติมาตรฐาน ซึ่งคุณจะต้องเจอกับรอบแบบนี้เป็นสิบๆ ครั้ง
- C — รอบที่ต้องมีการตัดสินใจ (Decision sessions) โดยมีตัวอย่างให้ดูว่าเวลาที่ Claude Code นำเสนอทางเลือกที่ดีมาให้นั้นหน้าตาเป็นอย่างไร และคุณควรจะตอบฟันธงกลับไปอย่างไร
- D — รอบของการสร้างและย้ายระบบ (Phase 4 BUILD sessions) รวมถึงการแยกให้ออกว่าตอนไหนระบบต้องการให้คุณเข้าไปช่วย และตอนไหนมันแค่รายงานให้ฟังเฉยๆ
- E — การสลับการทำงานระบบ (Cutovers) พร้อมสัญญาณเตือน 3 อย่างที่ถ้าเจอแล้วแปลว่าห้ามสลับระบบเด็ดขาด (เช่น "คิดว่าน่าจะโอเคนะ", เวลาตรวจสอบยังไม่ครบ, "ไม่มีข้อมูลเปรียบเทียบให้ดู แต่รันเทสต์ผ่านนะ")
- F — การสลับระบบที่เกี่ยวกับเงินและการล็อกอิน (Money/auth cutovers) ซึ่งต้องมีการตรวจสอบอย่างเข้มงวด และต้องสั่งให้ "รันให้ดูในระบบทดสอบ: ลองรันซ้ำสองรอบ แล้วดูซิว่าตัดเงินแค่รอบเดียวจริงไหม" เป็นท่าไม้ตาย
- G — เมื่อเกิดเหตุการณ์ไม่คาดฝันหรือระบบผิดพลาด ซึ่งถอดบทเรียนมาจากเหตุการณ์จริงที่คุณเคยเจอมาแล้ว

ส่วนท้ายของไฟล์จะเป็นนิสัย 5 ประการที่คุณควรทำ เพื่อให้ทุกอย่างทำงานได้อย่างราบรื่น

**ลำดับการอ่านไฟล์ในโฟลเดอร์คำสั่งของคุณ:**
ให้อ่าน `WALKTHROUGHS` (ไฟล์บทสนทนาจำลอง) เพื่อเรียนรู้และทำความเข้าใจภาพรวม → จากนั้นใช้ `SCRIPT` (ไฟล์สคริปต์) เพื่อเป็นโพยคำสั่งที่ใช้ในแต่ละรอบการทำงาน → ใช้ `HOW-TO-TALK` (คู่มือการสื่อสาร) สำหรับสถานการณ์เฉพาะหน้าที่เกิดขึ้นระหว่างทำงาน → สุดท้ายใช้ `OPENING-PROMPT` (คำสั่งแรกเปิดงาน) เมื่อคุณพร้อมที่จะเริ่มยิงคำสั่งงานแรก (Session 0-1)
