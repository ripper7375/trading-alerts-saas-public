SESSION-WALKTHROUGHS.md is created and placed in your prompt-to-claude-code/ subfolder alongside the other three prompt files (I noticed your reorg and moved it in, updated the script's header to point to it, and fixed the skeleton's path reference).

It teaches by complete played-out conversations rather than abbreviations. The key insight making it manageable: all ~60 sessions reduce to seven types, so it contains seven full dialogues with a mapping table telling you which walkthrough covers which sessions. It opens with "the rhythm" — the five beats every session follows (Advisor → your approval → open/go → work → close), with realistic time estimates showing your hands-on part is ~20–30 minutes per session.

Then the walkthroughs, each showing your exact paste, what a good response looks like, and the red flags meaning "don't say go": A — the 0-1 bootstrap, turn by turn, including a realistic F2 decision moment (what happens when next@16.2.10 doesn't exist on npm); B — the standard loop you'll run dozens of times; C — decision sessions, with a model of what a good options presentation from Claude Code looks like and how to answer narrowly; D — Phase 4 BUILD sessions, including telling apart escalations that need you from narration that doesn't; E — cutovers, with the three red flags that always mean no-cutover ("probably fine," clock not elapsed, "no diff but tests pass"); F — the money/auth cutovers with the audit interrogation and the "demonstrate it in staging: run it twice, show me one charge" fallback; G — when things go sideways, modeled directly on your real git incident. It closes with the five habits that hold everything together.
Reading order for your prompt folder: WALKTHROUGHS to learn → SCRIPT as the per-session reference card → HOW-TO-TALK for mid-session situations → OPENING-PROMPT when you're ready to fire Session 0-1.
