> **Session:** 4A-10b Pre-Cutover Verification · **Target:** Stripe Checkout Creation
> **Monolith Route:** `POST /api/checkout` → **Money-Service Route:** `POST /v1/stripe/checkout`
> **Feature Flag:** `MIGRATE_WRITE_APIS_MONEY_STRIPE=true`

---

## 🛠️ Ground-Truth Prerequisites & Environment Setup

### 1. Configure Stripe Secrets in `money-service` (Railway Dashboard)

Before testing Stripe Checkout through `money-service`, ensure `money-service` has the necessary Stripe API credentials:

1. Open Railway Dashboard (`https://railway.app`) → Select service **`money-service`**.
2. Click the **`Variables`** tab.
3. Add the following environment variables:
   ```env
   STRIPE_SECRET_KEY=sk_test_... (your Stripe API secret key)
   STRIPE_WEBHOOK_SECRET=whsec_... (your Stripe webhook secret)
   ```
4. Click **Save / Deploy**. Wait ~30 seconds for green deployment.

### 2. Identify Next.js Monolith Host & Environment Variables

The Next.js web application (owning `/api/checkout`) is deployed on **Vercel** or **Railway Next.js Web Service** (or running locally at `http://localhost:3000`):

- **If testing locally:** Set `MIGRATE_WRITE_APIS_MONEY_STRIPE=true` in `.env.local` and run `npm run dev`. Target URL: `http://localhost:3000/api/checkout`.
- **If testing deployed app:** Set `MIGRATE_WRITE_APIS_MONEY_STRIPE=true` in Vercel / Railway Next.js web service environment variables. Target URL: `https://your-domain.com/api/checkout`.

## 📝 Detailed Step-by-Step Instructions

### Prerequisite: Set Stripe Keys in `money-service`(DONE)

1. Go to **Railway Dashboard** → Click service **`money-service`**.
2. Click **`Variables`** tab.
3. Add `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`. Click **Deploy**.
   (DONE)

---

### Step 1: Enable Feature Flag in Next.js App (DONE)

1. Go to Vercel Dashboard (or Railway Next.js service) for the Next.js web application.
2. Under Environment Variables, set:
   ```env
   MIGRATE_WRITE_APIS_MONEY_STRIPE=true
   ```
3. Save and redeploy.
   (DONE)

---

### Step 2: Execute Initial Checkout Request in PowerShell

1. Open **Windows PowerShell**.
2. Copy the command below (update URL host and `<TEST_USER_JWT>`):

```powershell
curl -X POST https://your-domain.com/api/checkout `
  -H "Authorization: Bearer <TEST_USER_JWT>" `
  -H "Content-Type: application/json" `
  -H "Idempotency-Key: test-stripe-checkout-001" `
  -d '{"priceId": "price_1Pxxx_PRO_MONTHLY"}'
```

3. Right-click inside PowerShell to paste → Press **Enter**.

---

### Step 3: Verify Success Response (200 OK)

Check the JSON output displayed in PowerShell:

```json
{
  "sessionId": "cs_test_a1b2c3d4...",
  "url": "https://checkout.stripe.com/c/pay/cs_test_a1b2c3d4..."
}
```

_Pass Criteria:_ Returns HTTP status `200 OK` and a valid Stripe Checkout `url`.

---

### Step 4: Test Idempotency Key Caching (Duplicate Request)

Re-run the exact same `curl` command in PowerShell with the identical `Idempotency-Key: test-stripe-checkout-001`.

_Pass Criteria:_ Returns HTTP status `200 OK` instantly with the **exact same cached `sessionId` and `url`**, proving `IdempotencyInterceptor` prevented a duplicate Stripe API call.

---

### Step 5: Test Already PRO User Check

Execute the checkout `curl` request using a test user account that is already on the PRO tier.

_Pass Criteria:_ Returns HTTP status `400 Bad Request`:

```json
{
  "error": "Already subscribed",
  "message": "You are already on the PRO tier",
  "code": "ALREADY_PRO"
}
```

---

### Step 6: Verify Money-Service Logs in Railway

1. Go to **Railway Dashboard** → Click service **`money-service`**.
2. Click the **`Logs`** tab.
3. Observe log evidence:
   ```text
   [INFO] forwardWriteRequestToMoneyService: Forwarding POST /api/checkout -> money-service /v1/stripe/checkout
   [INFO] StripeCheckoutController: Created checkout session cs_test_a1b2c3d4 for user usr_123
   [INFO] IdempotencyInterceptor: Idempotency cache hit for key test-stripe-checkout-001
   ```
