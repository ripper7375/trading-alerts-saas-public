# Manual Smoke Test Procedure 3.2: dLocal Payment Creation Route

> **Session:** 4A-10b Pre-Cutover Verification · **Target:** dLocal Payment Creation
> **Monolith Route:** `POST /api/payments/dlocal/create` → **Money-Service Route:** `POST /v1/payments/dlocal/create`
> **Feature Flag:** `MIGRATE_WRITE_APIS_MONEY_DLOCAL=true`

---

## 🛠️ Ground-Truth Prerequisites & Environment Setup

### 1. Configure dLocal Credentials in `money-service` (Railway Dashboard) (DONE)

Sourced directly from your dLocal Merchant Dashboard (**Developers > Integration > API Credentials > Sandbox credentials**):

1. Open Railway Dashboard (`https://railway.app`) → Select service **`money-service`**.
2. Click the **`Variables`** tab.
3. Add/Configure the following variables:
   ```env
   DLOCAL_API_URL=https://sandbox.dlocal.com
   DLOCAL_API_KEY=... (your unmasked X-Trans-Key value from dLocal Dashboard)
   DLOCAL_SECRET_KEY=... (your unmasked Secret key value from dLocal Dashboard)
   DLOCAL_WEBHOOK_SECRET=... (your unmasked Webhook Secret key)
   DLOCAL_LOGIN=... (your unmasked X-Login value from dLocal Dashboard, optional fallback)
   ```
4. Click **Save / Deploy**. Wait ~30 seconds for deployment to turn green.

### 2. Identify Next.js Monolith Host & Environment Variables

- **If testing locally:** Set `MIGRATE_WRITE_APIS_MONEY_DLOCAL=true` in `.env.local` and run `npm run dev`. Target URL: `http://localhost:3000/api/payments/dlocal/create`.
- **If testing deployed app:** Set `MIGRATE_WRITE_APIS_MONEY_DLOCAL=true` in Vercel / Railway Next.js web app variables. Target URL: `https://your-domain.com/api/payments/dlocal/create`.

## 📝 Detailed Step-by-Step Instructions

### Prerequisite: Set dLocal Keys in `money-service` (DONE)

1. Go to dLocal Merchant Dashboard (**Developers > Integration > API Credentials > Sandbox credentials**).
2. Unmask and copy `X-Login`, `X-Trans-Key`, and `Secret key`.
3. Go to **Railway Dashboard** → Click service **`money-service`** → Click **`Variables`** tab.
4. Add:
   - `DLOCAL_API_URL` = `https://sandbox.dlocal.com`
   - `DLOCAL_API_KEY` = `<X-Trans-Key value>`
   - `DLOCAL_SECRET_KEY` = `<Secret key value>`
   - `DLOCAL_WEBHOOK_SECRET` = `<Webhook Secret value>`
5. Click **Deploy**.
   (DONE)

---

### Step 1: Enable Feature Flag in Next.js App (DONE)

1. Go to Vercel Dashboard (or Railway Next.js service) for the Next.js web application.
2. Under Environment Variables, set:
   ```env
   MIGRATE_WRITE_APIS_MONEY_DLOCAL=true
   ```
3. Save and redeploy.
   (DONE)

---

### Step 2: Execute dLocal Payment Creation Request in PowerShell

1. Open **Windows PowerShell**.
2. Copy the command below (update URL host and `<TEST_USER_JWT>`):

```powershell
curl -X POST https://your-domain.com/api/payments/dlocal/create `
  -H "Authorization: Bearer <TEST_USER_JWT>" `
  -H "Content-Type: application/json" `
  -H "Idempotency-Key: test-dlocal-create-001" `
  -d '{
    "country": "TH",
    "paymentMethod": "P2P",
    "planType": "MONTHLY",
    "currency": "THB"
  }'
```

3. Right-click inside PowerShell to paste → Press **Enter**.

---

### Step 3: Verify Success Response (200 OK)

Check the JSON output displayed in PowerShell:

```json
{
  "success": true,
  "redirectUrl": "https://sandbox.dlocal.com/pay/...",
  "orderId": "order-usr_123-1769550000"
}
```

_Pass Criteria:_ Returns `success: true`, a dLocal sandbox `redirectUrl`, and a formatted `orderId`.

---

### Step 4: Test 30s Idempotency Lock (Rapid Duplicate Request)

Re-run the exact same `curl` command immediately in PowerShell (within 30 seconds):

_Pass Criteria:_ Returns cached 200 response or lock busy response, preventing creation of a second `Payment` row or second API charge attempt.

---

### Step 5: Check Database Table in Railway

1. Go to **Railway Dashboard** → Click on database service **`Postgres`**.
2. Click the **`Data`** tab at the top.
3. Select table **`Payment`**.
4. Check the top (newest) row:
   - `user_id` = `usr_123`
   - `status` = `PENDING`
   - `provider` = `DLOCAL`
   - `order_id` = `order-usr_123-1769550000`

---

### Step 6: Verify Money-Service Logs in Railway

1. Go to **Railway Dashboard** → Click service **`money-service`**.
2. Click the **`Logs`** tab.
3. Observe log evidence:
   ```text
   [INFO] forwardWriteRequestToMoneyService: Forwarding POST /api/payments/dlocal/create -> money-service /v1/payments/dlocal/create
   [INFO] DlocalPaymentController: Payment lock acquired for user usr_123 (THB/MONTHLY)
   [INFO] DlocalPaymentService: Created dLocal payment order-usr_123-1769550000
   ```
