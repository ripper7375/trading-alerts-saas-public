## 📝 Detailed Step-by-Step Instructions

### Step 1: Enable Feature Flag in Railway

1. Open `https://railway.app` in your browser.
2. Select your project → Click on service **`trading-alerts-monolith`**.
3. Click the **`Variables`** tab.
4. Add or update the variable:
   ```env
   MIGRATE_WRITE_APIS_MONEY_DLOCAL=true
   ```
5. Click **Save / Deploy**. Wait ~30 seconds for green status.

---

### Step 2: Execute dLocal Payment Creation Request in PowerShell

1. Open **Windows PowerShell** (Windows Key → type `PowerShell` → Enter).
2. Copy the command below (replace `<TEST_USER_JWT>` with a valid test user token):

```powershell
curl -X POST https://staging.trading-alerts.com/api/payments/dlocal/create `
  -H "Authorization: Bearer <TEST_USER_JWT>" `
  -H "Content-Type: application/json" `
  -H "Idempotency-Key: test-dlocal-create-001" `
  -d '{
    "country": "TH",
    "paymentMethod": "P2P",
    "planType": "MONTHLY",
    "currency": "THB"
  }'
```

3. Right-click inside PowerShell to paste → Press **Enter**.

---

### Step 3: Verify Success Response (200 OK)

Check the JSON output displayed in PowerShell:

```json
{
  "success": true,
  "redirectUrl": "https://sandbox.dlocal.com/pay/...",
  "orderId": "order-usr_123-1769550000"
}
```

_Pass Criteria:_ Returns `success: true`, a dLocal sandbox `redirectUrl`, and a formatted `orderId`.

---

### Step 4: Test 30s Idempotency Lock (Rapid Duplicate Request)

Re-run the exact same `curl` command immediately in PowerShell (within 30 seconds):

_Pass Criteria:_ Returns cached 200 response or lock busy response, preventing creation of a second `Payment` row or second API charge attempt.

---

### Step 5: Check Database Table in Railway

1. Go to **Railway Dashboard** → Click on database service **`Postgres`**.
2. Click the **`Data`** tab at the top.
3. Select table **`Payment`**.
4. Check the top (newest) row:
   - `user_id` = `usr_123`
   - `status` = `PENDING`
   - `provider` = `DLOCAL`
   - `order_id` = `order-usr_123-1769550000`

_Pass Criteria:_ Exactly 1 new row exists matching the test `orderId`.

---

### Step 6: Verify Money-Service Logs in Railway

1. Go to **Railway Dashboard** → Click service **`money-service`**.
2. Click the **`Logs`** tab.
3. Observe log evidence:
   ```text
   [INFO] forwardWriteRequestToMoneyService: Forwarding POST /api/payments/dlocal/create -> money-service /v1/payments/dlocal/create
   [INFO] DlocalPaymentController: Payment lock acquired for user usr_123 (THB/MONTHLY)
   [INFO] DlocalPaymentService: Created dLocal payment order-usr_123-1769550000
   ```
