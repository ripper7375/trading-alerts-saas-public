## Decision

### D1. Nineteen locales, seventeen languages (amends ADR-038, 046, 056, 068 and 081)

The five ADRs above were written for 16 languages. The app has **19 interface locales** (`lib/i18n/languages.ts`): `en-US`, `en-GB`, `es`, `de`, `pt`, `pt-BR`, `it`, `ja`, `ar`, `fr`, `ko`, `zh`, `zh-TW`, `ur`, `hi`, `vi`, `id`, `th`, `tr`. They are 17 languages (English and Portuguese twice; Simplified and Traditional Chinese are two scripts), and the earlier "16" came from a count that left out the two regional variants and one script. The word **16 in those five decisions is read as 19 locales**, and every claim they make (the English pivot and glossary, the fixed out-of-scope reply, the wording guide and its phrase lists, the fixed Report 2 template, the safety texts and the right-to-left test) holds for all 19. Each of the five files carries an "Amended by ADR-098" line; their settled text is not edited (the file names keep "16" for history). The labelled set has 19 locale files, and "within 5 points of English" is measured for each. The list is read from `SUPPORTED_LANGUAGES`, not copied: a locale added there appears in the intake path at once and fails the pinned counts until a decision says so. (The step 6 task text named `ms` and `ru`; the app has `en-GB` and `pt`, and the code follows the app.)

The language of a reply is the language detected in the question, except that when the interface locale is of the same family it wins (`pt` text from a `pt-BR` user is answered in `pt-BR`; English from `en-GB` in `en-GB`); a language outside the list falls back to the interface locale; an instant prompt, which has no typed text, uses the interface locale.

### D3. The knowledge service is its own Railway service, with pinned requirements

txtai needs torch, which cannot live in the Vercel monolith. The service is a **new Railway service `knowledge-service`**, built from its own folder (root directory `knowledge-service`, watch paths `knowledge-service/**`), Python 3.11 with pinned requirements (txtai 9.5.0, CPU torch, faiss-cpu, FastAPI, uvicorn and the rest in `requirements.txt`). The corpus is built into the index **in the image build** ("rebuilt on every deploy", ADR-005, is the image build), so a failed gate is a failed build: `gate build --require-real --require-approved` then `gate replay --require-approved` are its last steps. The monolith calls `POST {KNOWLEDGE_SERVICE_URL}/search` (contract `knowledge-search/1`) with the shared secret in the header `X-Knowledge-Service-Key` (`KNOWLEDGE_SERVICE_KEY`); `GET /healthz` answers with the build id. If the index cannot load the service stays up and `/search` answers 503 with an unavailable pack, and any failure the monolith meets (not configured, timeout of 2 s, an error, a body that is not a knowledge pack) gives a packet with `knowledge.status = UNAVAILABLE`: Section 5 says the pack is missing and the trader still gets an answer. Not chosen: a sidecar in the `railway-gateway` image (torch in an image that rebuilds on every monorepo push, and the open question of Python there) and the Linux VPS (a manual deploy). Size (about 1.1 GB, estimated), memory (548 MB resident measured on Windows; plan 1 GB or more), the load time (8 s) and the latency (p50 30 ms on loopback) are measured on the pieces; **the image has never been built**.

### D4. The Understand step is an isolated adapter with a schema-validated answer

ADR-039's one small model call is a port, `UnderstandPort`, answered by one thin adapter (`lib/intake/text/understand-model.ts`): OpenRouter's OpenAI-compatible `chat/completions` through one `fetch` (no SDK, no dependency), a model named by the environment (`INTAKE_UNDERSTAND_MODEL`, so the code holds no id that can go stale), a key in the environment (`INTAKE_UNDERSTAND_API_KEY`) that appears only in the `Authorization` header, an optional base URL (`INTAKE_UNDERSTAND_BASE_URL`, https or http on this machine), temperature 0, `max_tokens` 700, `provider.data_collection: "deny"` (ADR-077), a budget of one second per attempt and one retry for a timeout, a network error, a 429 or a 5xx, none for a 4xx. The adapter returns text and checks nothing: `runUnderstand` holds the answer to `understand-result/1` and to the term-preservation check, and any failure, there or in the adapter, is one refusal, `UNDERSTANDING_FAILED`, in the interface language, with nothing else run and nothing charged. That is the new degraded-mode row ADR-078 needs. Step 7's model gateway replaces the adapter behind the same port. **The adapter has not been called against a real endpoint**, and no key exists; the recorded run of the labelled set is a stand-in until one is made.

### D5. The quota pre-check is a port, and nothing meters it yet

Units do not exist until step 7. The gate asks a `QuotaPort` before any model call, in the fixed order flag, session, tier, thread, profile, quota. The default adapter says "not metered, allow", and the tests use a fake that refuses, which proves the gate (an instant prompt with too little quota is refused before anything else runs, in the interface language, 19 locales). **Consequence, and a rule: `INTAKE_ENABLED` stays `false` in production until step 7 meters.** With the flag on and this adapter, any signed-in Pro trader could call the route without limit; the runbook says so in its first lines. Not chosen: an interim adapter on the Redis token counter (it has no read-only call and counts tokens, not units).

### D10. The Panel C instant prompts are the two top-left Market Context badges (Owner Decision "Option A")

**Settled by Davin on 2026-10-14**, replacing the first build of this decision (a separate "Explain the current M5 / M15 chart" button at the bottom left of each pane, `6d265c5b`). The part 10 hand-off (section 6, reading 1) had asked only which of two texts the button should show; the Owner Decision answers a wider question and **removes the button**: the instant prompt is the badge the chart already carries at its top left, so the pane gets no second control and no bottom-left clutter.

The layout is the one the code has (`upperTimeframe = 'M15'`, `lowerTimeframe = 'M5'`): M15 in the upper pane and M5 in the lower one. The badges read `[DavinTrade logo] XAUUSD · M15 Market Context •` (upper) and `[logo] XAUUSD · M5 Market Context •` (lower), the trailing dot marking the active pane. The pieces: `components/charts/ask-ai-button.tsx` (`MarketContextBadge`; the file keeps its part 10 name), `components/charts/use-instant-prompt.ts` (the press, unchanged), wired into `components/charts/mtf-stacked-charts.tsx`, which hands the badge to `TradingChart`'s existing `overlayBadge` box. Nothing is added to the pane, so `TradingChart`'s own strip, `mtf-split-layout.ts` and `CHROME_PER_CHART` (86) are untouched (a test holds the same canvas heights with the flag on and off).

- **A press posts `{ "kind": "INSTANT_M15_INSPECT" }` (upper badge) or `{ "kind": "INSTANT_M5_INSPECT" }` (lower badge) and nothing else** to `/api/intake/instant`: no text, no language, no thread. The server reads the interface setting and uses the fixed English question of the kind for retrieval ("Explain the current M5 chart", read by the matrix with M* = the sensors of the M5 channel plus the always set, domains D1 and D3, D2 for M*). An instant press never also calls the chat panel's `onAskAi`.
- **For a Pro trader** the press makes the request. While it is in flight **both** badges are disabled and `aria-busy` (one request in flight for the whole chart, so two presses cannot both pass the quota pre-check), the pressed badge shows a spinner (a `Loader2`, in the place of its active dot), and a second click is ignored, also within the same tick. A refusal appears **below the badge** as the server's own reply, already in the interface language, and goes away after 12 seconds or at the next press; any other failure (a 404 while `INTAKE_ENABLED` is off, a 5xx, no network) shows the fixed "not available" text of the dictionaries. A success is handed to an optional `onInstantResult` and nothing is drawn: **rendering the reply is step 7's**.
- **For a Free trader** the badge is shown (it was not before: the older badge is for Pro) and a press opens the existing upgrade modal (`onOpenUpgradeModal`); no request is made. A Free trader with no upgrade modal to open gets no badge rather than a dead one. **One consequence:** the lower pane of a Free trader also holds a centred "tools are unavailable" banner, which would cover the badge at the top left; while the badge is shown the banner sits just below it (`top-[42px]`), and with the flag off it stays centred as it always was.
- **The flag is read on the server.** `isInstantPromptsEnabled()` (`INTAKE_INSTANT_PROMPTS_ENABLED` exactly `true`, set nowhere) is read by `app/terminal/page.tsx` and `app/free/page.tsx` and passed down as a prop through the two workspace shells and `TradingWorkspace`; the browser never sees the variable. **With the flag off the badges are the older ones** (Pro only; a press hands a canned prompt to the chat panel through `onAskAi`). It is not a second lock on the route (the route answers 404 until `INTAKE_ENABLED` is `true`), and the flag stays off until step 7 renders replies.
- **The text.** The badge's visible text is the badge's own (`XAUUSD · M15` and the translated "Market Context"); its accessible name is that text, the logo is decoration. What a press asks is its **tooltip**, the dictionary text of the fixed question (`intake.instant.m5` and `intake.instant.m15`, "Explain the current M5 chart" and the M15 one), which part 3 translated into all 19 languages. The older label "Ask AI about M5 Chart" is no longer shown anywhere. The refusal wraps rather than growing past the pane (German and Thai, looked at at 320 px) and runs right to left in Arabic and Urdu; the chart itself stays left to right.
- `app/dev/intake/instant` shows the real badge and hook over a stand-in route in every state; like its parent, it answers 404 in a production build.

### D11. Retrieval configuration

One query, one SQL statement, bound parameters (§4.7). `weights=0.7` (a single value gives 0.7 to the dense score and 0.3 to the keyword score) and **`normalize: true`** on the keyword scoring, because txtai adds weighted scores only when the keyword index returns normalised ones and otherwise fuses by rank, where 70/30 would weight rank positions; the index config is pinned (`parse_index_config` refuses `normalize: false`), the loader refuses an index saved with other scoring, and a test fails if either setting changes. The candidate window is `similar(:q, 40)` with `LIMIT 4`, and stays 40 (the worst pre-filter rank over 386 searches on 141 chunks was 4; 80 and 141 gave the same recall). Domains come from the dispatch matrix, not from the request; the D2 playbooks are searched only for the registered sensors of M\* and only where the matrix says so; empty lists build no clause and an empty scope answers EMPTY without searching. **The intent templates are one word each** (`direction`, `entry`, `targets`, `risk`, `explain`, `news`; `M5` and `M15` for the instants): the longer ones let the template pick the chunks, and the labelled set found one word the best form by one question (24/30 against 23/30 with none or with two words). Chunks are split over **450** tokens, counted with the model's own tokenizer (ADR-043's step 3 said 1,500; the dense vector sees only the first 512 tokens, so a longer chunk is partly invisible). The rule-id tag the plan named is not built; three questions about a rule id are a ledger of expected failures.

### D12. The embedding model is pinned by hash and baked into the image

ADR-045 said "an English MiniLM-class model". It is **`sentence-transformers/all-MiniLM-L6-v2` at revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`** (Apache-2.0 per the model card), fetched once at image build time (the weights only: about 92 MB) to a local directory, and the process runs with `HF_HUB_OFFLINE=1` afterwards; nothing is downloaded at start. The revision is part of the index build id, so a different model or revision is a different build and needs a new decision.

### Recorded here because they were decided with the step and bind it

- **D6, no chat table.** The thread is a well-formed optional id checked by a `ThreadPort`; there is no `chat_threads` migration. Step 7 owns the sessions API and the transcripts.
- **D7 and D8, the board with nothing live and its price.** With no live sensor the board says so in words and the packet carries `SENSORS_NOT_LIVE`; the DATA line's price is the close of the last closed M5 bar of the stored reading, labelled with the bar (not the forming bar's price).
- **D9, the packet.** It pins the cycle slot, carries an `events` block with the calendar's age for every intent except Out of scope, a six-field profile that is scanned for `equity` and `commission` at any depth, and `knowledge` null for Report 2.
- **D14, translations.** The 18 non-English glossaries, texts and question sets are drafts no native speaker has read, and the ten refusal replies also wait for counsel; **the intake flags stay off until they are read** (as Engine 4's did).
- **D15 (c), two bars added to ADR-044's four:** the out-of-scope questions are refused in **100%** of every language, and at most **5%** of the in-scope questions may be wrongly refused by the scope check (a starting value; of the 35 in-scope questions of a locale that is one). The labelled set is 40 questions per locale (760 in all), so one miss is 2.5 points and "within 5 points" tolerates two. The English base is approved by Davin; a recorded run must be made again whenever the model, the prompt, the glossary or the set changes (the fingerprint says so).
- **The scope check reads `2day` as "today".** Typed as one word it is text-speak for "today", not the two-day timeframe D2; `2 day`, `2-day`, `2days` and `2d` are still D2.

## Alternative not chosen

Multilingual embeddings (ADR-038 stands); vector routing before the rules are beaten on the labelled set (ADR-036 stands); the sidecar and the VPS for the service; the model gateway of step 7 in this step; a Redis stand-in for the quota; showing the instant prompts only for Pro; putting a control in `TradingChart`'s strip (the M15 toggle already fills it, and the strip is part of the split arithmetic); a separate button at the bottom left of each pane (the first build, replaced by the badges on 2026-10-14: it cluttered the chart canvas and put a second control beside the badge that already says what the pane is).

## Why

The step builds the whole first half of the request, so that Section 5 and the chat have a tested packet to stand on: every question is answered from one board, one routed set of sensors in full and a pack the service could not fake. It is built so that a missing piece degrades to a packet with a flag, never to a wrong answer. The decisions above are the ones a later reader would otherwise have to re-derive from the code, and the three that involve money, a secret or a new service (D3, D4, D5) are recorded with what they leave open.
