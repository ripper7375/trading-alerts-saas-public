## 6. Decisions needed from Davin, with the options seen

None blocks part 3. Each is a reading where the approved text left a choice, or a consequence worth seeing.

1. **D7 (e) read literally: a level between the reference price and the zone's far edge is both confluence and the opposing level.** "Beyond the reference price" counts it, so a resistance 0.76 above the entry (18 Sep, `sr_2` against the LOEDT zone) sets a runway of 0.76 although it also marks the zone. That is the conservative reading and what the test cycle item ("a level just above entry blocks targets") asks for. The alternative, running the runway from the zone's far edge, would not count a level inside the zone as an obstacle. Keep as built?
2. **M15 levels follow the rules D5 gave `sr_*`** (invalidation, opposing level, confluence when inside a zone; no zones of their own). D6 says "M15 as structure" and D5 describes what structure does, so I read them together. Say if M15 levels should not count as confluence.
3. **Levels come from every available sensor, not only those the matched rule read.** A Day Trader's row 2 reading through MCD1 alone still gets M5 levels from MCD2. Alternative: only the sensors read (then that reading would have no zone sources).
4. **A LONG with no zones is a real outcome**, not an edge case: on 28 Sep 14:15 both readings are LONG (row 2, the snapback) but the price is below the whole M5 channel, so nothing lies on the bias side to make a zone from (`NO_ZONE_SOURCES`). That is D6 as approved; I am reporting it so Report 1's wording (step 7) expects it.
5. **The `context_levels` shape I built the reader for** (part 3 must produce it): `{"M5": {"sr_1": 4369.57, "sr_2": null, ...}, "M15": {...}}`, the last closed bar's `sr_1` to `sr_16` of each timeframe, `null` for a slot that resolved no level. The same slot at the same price on both timeframes is one level.
6. **A zone carries more than 3.6's row** (the levels it was made from, the levels inside it, the invalidation basis and the level it sits behind), so it can be audited and replayed. Part 4 decides the columns; the extra fields can live in a JSON column.
