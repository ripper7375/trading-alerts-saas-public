## 6. Decisions needed from Davin

None blocks part 4. One design choice to confirm, low urgency:

1. **A slot that was superseded before its manifest was built gets no manifest.** Only the newest validated slot is built, which is the newest-first rule applied to manifests; if the worker falls a whole slot behind, that slot
   leaves no `market_cycles` row and the gateway reports DELAYED or STALE for it, an honest hole. The alternative is to also send late manifests for the last few slots (each would arrive after its slot was already
   overtaken, so the sensor job it queues would be of little use). Recommend keeping it as built. It bears on §1.8 "one `market_cycles` row per slot", which is only fully true while the worker keeps up.

## 7. Problems and surprises the next session must know

1. **Time to ready now includes sending 386 single-row requests before the manifest.** At the 375 to 600 rows a minute ADR-013 cites that is about 40 to 60 seconds, plus the collector's own time, against the 2-minute ready deadline of ADR-012
   (both are starting values). It may be tight. Not changed: part 10's measurement settles it, and the options are then a batch endpoint (a contract change) or a smaller priority set.
2. **By default an export carries no "Export Time" line at all** (`InpIncludeMetadata = false` in `ohlcvexportlightweight_v2_29.mq5:29`, and the repository's sample exports have none). The file's modification time is therefore the only export
   time available, which is what Davin chose. When the line is switched on it is the last tick's broker time, not the write moment (part 2, §7 item 1).
3. **The "finished" marker is what the manifest waits for.** The collector stages statistics after marking a cycle validated, so without it a manifest could report zero snapshots for a slot that has them. A collector that crashes
   between validated and finished leaves that slot without a manifest (consistent with the gateway then reporting the slot late or stale).
4. **`export_collector_validator_v2.py` is CRLF in the working tree** (index LF); the push worker and the SQL are LF. The edits keep each file uniform. Recorded in `environment-gotchas.md` with the trap it caused my scripts.
5. **A worker updated before its collector, or a collector deployed beside an old schema file, now says so once** (a warning naming the missing columns or the `cycle_manifests` table) instead of silently switching the lane off. The deploy
   package `DEPLOY_TO_CONTABO_VPS_READY/Python_Scripts` holds older copies of the two `.py` files and no schema file: it was not updated.
6. **The fixtures drop `trg_market_data_prune`**: with it, building 6,000 rows took 176 s per test file; without it, 3 s. Nothing in these tests is about retention. Recorded in `environment-gotchas.md`.
7. `repush_rows_unsent` is deliberately not sent (the collector does not track which rows a promote re-queued); the contract says absent means "not measured", which the gateway must not read as zero.
8. The existing `quarantine_row` and the 400 handling are unchanged in behaviour; a manifest the gateway answers 400 is quarantined to `rejected_manifests.jsonl` and never resent, while 404, 5xx, timeouts and 429 are retried and never stamp it.
9. Importing the push worker creates `C:/Scripts/logs` on the machine running the tests (existing behaviour, as for `test_push_economic_events.py`); the new tests redirect every quarantine file into a temporary folder.
