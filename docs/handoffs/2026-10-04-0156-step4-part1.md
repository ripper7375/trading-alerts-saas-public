## 1. Done in this session

- **The rules file `draft-1.yaml`:** architecture 3.4 transcribed as the ordered, versioned file of ADR-026 (rows 0, 1, 2, 3, 3s, 4, 5, no match, and the MCD3 modifiers), with each reading of decision D1 (a) to (e) written down in its header. Its checksum is taken over the parsed document (line endings, comments and spacing cannot change it) and is pinned by a test.
- **The loader and checker (`rules.py`, `facts.py`):** reports every problem at once; refuses unknown and duplicate keys, a state or regime word that is not in the sensor's register, a fact the sensor does not have, a YAML boolean where a word was meant, a row order that does not start with the data check, and any text with a banned word, a percent sign, an advice word, a summary over 80 characters or a price.
- **The engine (`engine.py`):** `decide` is a pure function of the rules, a trader type and the sensors' readings: row 0, first match, the primary sensor's branch first on rows 2 and 4, an unavailable sensor cannot match, MCD3 as modifier (never a vote), caution inherited from the sensors the matched branch read (D3), no match recorded as NEUTRAL.
- **The reading (`reading.py`, `syn-output-1.schema.json`):** `synthesize_cycle` gives the Day Trader and the Scalper reading of a cycle; canonical JSON and its SHA-256; guards for the schema (which states the invariants), the reason codes, the identity (version, checksum, row, branch) and the wording. A reading that fails is returned with its problems and must not be saved; nothing raises.
- **The specification `synthesis.md`:** the table as built, every reading of 3.4 where it was silent, the SYN fields, and six things worth knowing (its section 7; they are repeated in section 7 below).
- **Tests:** 180 new (rules 49, engine 80, reading 42, fixtures 9), including a differential test of the engine against an independent reading of the table over all 810 state combinations for both trader types.
- **Mutation check:** 114 new mutants of the four new source files; **all 114 killed in the final run on the final code** (the first run killed 113 of 115, see section 3).
- **Three existing files edited on purpose:** `test_boundaries.py` (the new subfolder is pinned and brought under the same import, write and clock guards as the runner), `tools/mutation_check.py` (an optional per-mutant `modules` field, the four test modules in the run list, the 114 mutants), `mcd_worker/README.md` (a section).

## 6. Decisions needed from Davin, with the options seen

None blocks part 2. These are my readings where the approved text left a small choice; say if any is wrong.

1. **A data stand-aside is an INVALID or STALE reading.** D1 (a) says STAND_ASIDE with a data reason. I made the reading STALE (`UPSTREAM_STALE:MCD1`) when the primary sensor is STALE and INVALID (`UPSTREAM_UNAVAILABLE:MCD1`) otherwise, with bias STAND_ASIDE, no archetype and no zones, reusing the kit's reason codes. Alternative: VALID or CAUTIONARY with the data reason only in `reasons`. The first lets the answer gate (5.3) and the sensor board treat it like an unavailable sensor; a consumer that only asks "is there a direction" reads `stand_aside` either way.
2. **A cycle with no match counts every available sensor as read** for caution (D3 speaks of "the sensors the matched rule read"; there is none). So a NO_MATCH reading is CAUTIONARY when any available sensor is. Alternative: always VALID.
3. **MCD3's own reason codes come along whole when a modifier applied**, including its `UPSTREAM_CAUTIONARY:MCD1` and `:MCD2`, even where the branch did not read MCD1 (a Scalper's row 3s). They duplicate what MCD1 and MCD2 already say. They could be left out; this is engine behaviour, not the rules file, so no new rules version is needed.
4. **The first row for each trader type must be the data check**: the loader enforces what 3.3 mechanic 1 says. A rules file that moves it is refused.
5. **`inputs` has an object per sensor** (status, state code, regime word, bias, envelope hash) and the reading adds `status_reasons`, `data_status`, `rules_sha256` and `branch_id`. The 3.5 example shows one word per sensor, not the same kind of word each time. 3.5 is corrected in part 7 unless you object.

## 7. Problems and surprises the next session must know

- **On all three real cycles every SYN reading is CAUTIONARY** (MCD0 flags both timeframes, so every channel sensor is). 3.5's example shows VALID. The golden scenarios and 3.5 will say CAUTIONARY.
- **Row 5 can never fire for a Scalper, and a Scalper never gets NO_MATCH with a usable MCD2** (rows 2, 3s and 4 cover every state of MCD2; row 0 covers an unusable one). For the Day Trader row 5 fires only when nothing above matched. A test pins both.
- **The real cycles hit rows 1, 2, 3 and 3s; rows 0, 4, 5 and no match are shown on synthetic readings only** (part 7's golden scenarios cover them with files).
- **Python's `$` matches before a trailing newline**, so `re.match(r"^x$", "x\n")` succeeds; every pattern in the new code uses `fullmatch` and a test pins it (a version name or a state code with a newline is refused).
- **A shell heredoc that holds Python source with `\n` escapes misbehaved in this environment**; edits that needed exact multi-line strings were done with the Edit tool or a script file in the scratchpad. A markdown file with wide tables needed up to three `prettier --write` passes to settle.
- **The mutation tool now takes an optional `modules` per mutant**: synthesis mutants run against the four synthesis test modules only (a survivor is then a gap in those tests); the 231 earlier mutants still run the whole suite, and six of them were re-run as a sample.
- **New files were written with LF; git warns that it will convert them to CRLF on touch** (this checkout is CRLF). Harmless; no file the gateway copies byte for byte was touched.
- **The sensor kit sync list does not include `synthesis/` yet** (the plan puts that in part 5, assumption A2); `mcd_worker/README.md` says so.
- **Not checked:** nothing ran against production, the Railway image or a database; the six real readings were made from the stored envelopes in `fixtures/*.cycle.json`, not from a live cycle; the 16-language texts of the reasons are step 6.
