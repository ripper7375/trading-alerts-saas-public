### How a reader decides

1. **Which cycle vouches.** For a timeframe it is the cycle at the slot where that timeframe was last collected (rule 5): M5 at the slot itself, M15 at the last quarter hour. `getOneDayOhlc` needs both. The cycle must be READY and well-formed, or the answer is STALE (`CYCLE_NOT_READY`, `INVALID_CYCLE_ROW`).
2. **Bars.** The newest `n` rows at or before the last bar that is closed at the slot (rule 2), oldest first; every bar returned is re-checked with `isClosedBar`; fewer than `n` is STALE (`INSUFFICIENT_CLOSED_BARS`), never padded.
3. **Last price (rule 3).** The close of the M5 row that opened at the slot, nothing else of that bar, labelled with the export file's time. It is offered only while that row is still the version this cycle wrote (`row.cycle_id` equals the cycle's `m5_collection_cycle_id`): after the next cycle rewrites it, it is `UNAVAILABLE / NOT_THIS_CYCLES_PRICE`.
4. **Statistics (rule 5).** One `findUnique` on (symbol, timeframe, source, `captured_at` = the collected slot). No row is STALE: `STATISTICS_SHORTFALL` when the cycle went READY recording a shortfall for that timeframe, otherwise `NO_STATISTICS_AT_SLOT`.
5. **Replay.** `getOneDayOhlc` hashes what it read and compares it with the digest stored at READY: `matches` is true, false (a closed bar changed since) or null (none stored).

## 7. Problems and surprises the next session must know

1. **The labelled last price is only as good as the newest-row answer.** If the VPS query shows the newest row is the bar that is about to close (not the new-bar stub), there is no row at the slot, and the reader says `FORMING_BAR_NOT_IN_TABLE`; it never borrows the last closed bar's close. That would need another source for the price line, decided when the answer is known (`waiting-on.md`).
2. **The price is a live value by nature**: once the next cycle rewrites the row (with the closed bar's final values) it is `NOT_THIS_CYCLES_PRICE`. Section 5 must read it within the 5-minute window, or accept `UNAVAILABLE`. Replays of old slots therefore never carry a price.
3. **M15 is vouched for by the cycle that collected it.** At an M5-only slot, M15 reads are STALE when the quarter-hour's cycle is not READY, even if the M5 cycle of the slot is fine. This is rule 5 applied to bars as well as statistics.
4. **The sensor worker must retry on `CYCLE_NOT_READY`.** The `cycle-ready` job is announced just before the row is marked READY (part 4, announce first), so a consumer can pick it up a moment early and see PENDING. The job's payload carries `readyAt`, `dataStatus`, `attempts` and the digest.
5. **A hole in the middle of a window is not detected by the readers.** They count bars (a day is 288 and 96) and check the newest, but do not check that consecutive bars are contiguous trading bars; the landed check at READY time counted rows between the manifest's oldest and newest bar, which is the cover for a hole. A gap check inside the window would need the market-hours gate per bar; not built.
6. **The guard found one offender and I did not change it**: `lib/indicator-statistics/queries.ts:55`, in a known-legacy list inside the guard spec with its reason; the spec fails if the entry stops being true, so the list only shrinks. The scan skips `legacy/` archives: the superseded MCD evaluators there sort workbook rows by `captured_at` and take the newest. The retrofitted MCD kit enforces the slot match itself (`mcd_common/cycle_inputs.py`). The scanner cannot see a value computed in one query and passed as the exact `captured_at` in the next, nor workbook handling in Python; it is a net for the common mistake, not a proof (its header says so).
7. **`check_detail` is a free JSON column**, read defensively: a record that says STATISTICS_SHORTFALL but cannot say for which timeframe counts for both; a map that lists timeframes but not this one means nothing was short for it. My first version got the second case wrong; the integration test caught it.
8. **The closed-bars query was moved** out of the manifest service into one shared function. The manifest service's digest and every reader now share it; the old inline copy is gone.
9. **The in-memory Prisma is now stricter** (a missing `state: 'READY'` returns the PENDING row; no `findFirst` on statistics). The real-Postgres spec exists because a fake can only show what its author thought of; it is gated and skipped in a normal `npm test`.
10. **Jest in this package only finds specs under `test/`** (the `testRegex` needs that path segment), so a one-off spec in a scratch folder is never found even with `--roots` or `--config`. The throwaway check had to be copied into `test/` and deleted. Recorded in `environment-gotchas.md`.
11. **The part 4 scratch Postgres spec is obsolete**: its bars carried `cycle_id` 1, which the strengthened check now (rightly) treats as an older cycle's copy. The repository spec replaces it.
