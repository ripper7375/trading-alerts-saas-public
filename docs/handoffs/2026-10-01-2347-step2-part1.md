Behaviours of the new code to know about, for confirming the ADR-012 values on the first real cycles (none needs a decision now):

- **After the market reopens, the status is STALE until the first cycle of the new session is ready (about 6 minutes).** The newest cycle then belongs to the previous session.
  This is literal rule 7 ("no ready cycle for 10 minutes") and it blocks direction and zones when there is genuinely no fresh data. Counting only open-market time instead would have
  labelled Friday's data FRESH on Monday at 01:02 server, which is the wrong direction, so the literal reading was kept.
- **The live status uses the 2-minute deadline, because retries are not visible until a cycle completes.** A cycle the collector retries can read DELAYED for up to two minutes and
  then be stored FRESH (4-minute deadline). The conservative side is deliberate.
- Boundaries are inclusive for "in time" (ready exactly at 120 s, or 240 s with a retry, is FRESH) and STALE starts at exactly 600 s since the last ready cycle.
- A cycle row that cannot be right (slot off the boundary, ready before its slot, attempts below 1) fails closed to STALE with reason `INVALID_CYCLE_ROW`; `cycleStatus` throws on it.

## 7. Problems and surprises the next session must know

1. **Part 2 must carry `attempts` on `market_cycles`.** `cycleStatus` takes `{ slot, readyAt, attempts }`: the collector attempts the cycle needed decide the 2-minute or 4-minute deadline. The plan's
   Part 2 list had status, timings and cycle ids but not this field, and Part 3's manifest must report it per collection cycle (the collector's `open_cycle` already returns the attempt number).
2. **Where the monolith gets the status function is still open** (the plan's open point for Part 1). Nothing in the monolith needs it until the chapter 5 gate (step 7), so the question is parked:
   a copy pinned by a sync test (the pattern the Prisma mirrors use) or a workspace package.
3. **`railway-gateway` has no working lint.** `npm run lint` matches no files: the package has no ESLint config and the root `eslint.config.mjs` ignores `railway-gateway/**`. Its `tsconfig` also excludes
   `test/`, so `tsc` does not type-check the specs (ts-jest does when they run). Pre-existing, left alone; recorded in `environment-gotchas.md`.
4. **The specs read the collector's source** (`TF_SECONDS`, `CYCLE_INTERVAL_SEC`, `MAX_ATTEMPTS_PER_CYCLE`, `RETRY_WAIT_SEC`, `MAX_BAR_LAG_MULTIPLIER`) by regular expression, like `dto-contract.spec.ts` does for the
   gateway contract. Renaming one of them fails a spec on purpose.
5. **The parity evidence ends on 2027-12-31.** The port is computed, not tabulated, so it keeps working, but re-run `scripts/generate_market_hours_parity.py` (then Prettier) after any change to the collector's
   gate and before relying on parity past 2027.
6. **DST is modelled as the collector does** (2nd Sunday of March to 1st Sunday of November, 00:00 UTC). The US change itself is a few hours later on that Sunday, but the server day is Sunday under either offset
   (closed until Monday 01:01), so open/closed answers cannot differ. Whether the broker's clock actually follows the US rule is taken from the collector and not verified. The chapter 7 blackout test is separate.
7. **Stale mentions left alone on purpose:** `docs/MCD-DEVELOPMENT-STANDARD.md:798` says "(ADR-015, proposed)" (the standard is versioned, so that edit belongs to the MCD track) and
   `docs/STACK-D-BUILD-USER-MANUAL.md` lines 156 and 646 still list "confirm or replace ADR-015" as a pending decision (Davin's document). Both are for the advisor to schedule.
