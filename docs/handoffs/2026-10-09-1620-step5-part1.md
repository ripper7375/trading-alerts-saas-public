## 6. Decisions needed from Davin, with the options seen

The plan's D1 to D17 are settled. These are the points where the plan or the architecture was silent and I had to read. **The recommendation is the default, and it is what is built.** Each is a one-line change.

1. **The leverage steps (1 and 4) use the FILL price** (money maths, so yours). D3 says a BUY fills at the ask (entry + S) and a SELL on the bid, and changes the loss and gain per ounce and the trigger levels; it does not say which price the position is valued at for leverage. I used the fill price (entry + S for a BUY), so "leverage used is never above the limit" holds for the order as it is really opened. With S = 0 it is the 6.7 table. (a) fill price (built); (b) the chart entry, as 6.7 is literally written, which can put a BUY's real leverage a hair over the limit (about 0.01% on gold). _Recommend (a)._ The equity fact for the leverage limit uses the same price.
2. **The broker's maximum lot (`volume_max`) is a third limit in step 3.** The 6.7 table has two. A lot above the broker's maximum cannot be placed, so `limitedBy` can be `BROKER_MAX`. It never binds on gold at ordinary equity. _Recommend keeping it._
3. **The counter-trend cap, in two places (D5 gap).** (i) On the PROFILE the 2.50 cap is refused only for the Trend Countering style; for Both the profile may hold up to 3.50 because the cap is applied per setup (ADR-064), and 6.2's "counter-trend styles" could also be read as including Both. (ii) On a counter-trend SETUP whose profile RRR is above 2.50, Normal is lowered to 2.50 (the result says `normalCapped`), Conservative is 2.25, Aggressive is left out. The architecture says only that Aggressive is capped. _Recommend as built;_ the alternative for (ii) is to refuse the setup, which blocks a trader whose profile is valid.
4. **Custom leverage has no lower bound except "above zero".** 6.2 gives presets from 1:1.0 and a ceiling of 1:5.0, nothing below. _Recommend as built;_ a floor of 1.0 is one constant.
5. **Underflow wording is the template's job, the numbers are exact.** "Raise risk to X%" is rounded UP to 0.01% so that entering it really buys a lot (3.008% is offered as 3.01%; 3.00% would not be enough, and a test shows it). "This setup needs at least $X of equity" is an exact fraction; show it rounded UP (to the cent: $2,911.47; or to the dollar: $2,912) so that "at least" stays true. Rounding to the nearest would sometimes say a figure that is one cent short. For part 7.
6. **A broker row that contradicts itself is refused, not repaired:** the minimum lot must sit on the lot step (so "round down to the step" and "at least the minimum" cannot disagree) and the maximum must not be below the minimum. Real MT5 rows satisfy both; the exporter's validator could check the same.
7. **An underflow still returns the scenarios' targets** (distance and price need no lot), with `netProfit: null`. Part 7 can show them or hide them.
8. **The fixture is 2.3 MB (72,778 lines) after Prettier.** (a) as is; (b) add it to `.prettierignore` and write it compact, one case per line (about 0.7 MB; the MCD fixtures are handled that way); (c) fewer generated cases (480 now). It only matters for the diff size. _Recommend (a)._
