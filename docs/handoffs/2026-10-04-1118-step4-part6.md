## 6. Decisions needed from Davin, with the options seen

None blocks part 7. Each is a choice I made that is yours.

1. **The replay asks for the STORED rules version, and only falls back to the engine's current one when that file is gone.** Alternative: always the current version (simpler), which would make every replay of a `draft-1` cycle a VERSION_MISMATCH the day `draft-2` becomes current. It depends on the rule you set (a rules file is never edited in place and never removed once used, ADR-026): remove one and its cycles replay as VERSION_MISMATCH, not as a defect. I recommend keeping it.
2. **A reading the gateway refused is a note in the replay, not a verdict.** The replay makes both trader types; a type with no stored row is listed (`notStored`) with a note that names `SYN_READING_REFUSED`, and the cycle can still be VERIFIED for what is stored. Alternative: a verdict, which would turn every GATEWAY refusal into "not deterministic" in the kit. The kit's gap check (a cycle with fewer SYN rows than trader types, explained or not) is where a refusal is accounted for. I recommend keeping it.
3. **A changed sensor explains a changed SYN reading.** SYN reads the sensors' envelopes, so when MCD1's evaluator version changes, the SYN reading that read it changes with it; that reading is VERSION_MISMATCH and names the sensor, not a SYN divergence. A sensor that diverged does not hide a SYN difference: it stays LOGIC_DIVERGENCE and says the sensor diverged too.
4. **Refusals are counted from the log and the outcomes, as you approved; the limits are printed in the report.** Bull keeps the last 100 completed jobs, so with `--redis` alone the gap check looks only at the slots those jobs cover; a `--log` is taken to cover the range asked about. A table (`synthesis_refusals`) would make it a database fact and would be a new migration; I would wait for B1 to show how often a refusal happens.
5. **The kit has its own copy of the wording lists** (banned words and their inflections, advice words, 80 characters) because `wording.py` is Python. A spec reads the Python file and requires equality, and runs both implementations on a corpus of texts and codes when Python is there. A new banned word means `wording.py` first (standard 7.4), then the kit.
6. **A `NO_MATCH` reading and a cycle with fewer SYN rows than trader types are findings** (`--strict` exits 1 for them). The shadow stage exists to find them; say if you would rather see them as figures only.
