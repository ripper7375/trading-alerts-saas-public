## 7. Problems and surprises the next session must know

- **The pre-commit hook reformatted the MCD2 fixtures and broke two tests on the first commit.** `lint-staged` runs `prettier --write` on every staged `.json`, `.md` and `.yaml` file. The one-line canonical `.inputs.json` fixtures became about 3,700 lines each, and the envelopes and `mcd2_output.json` were re-laid out, so `test_t9_the_stored_fixtures_replay_byte_for_byte` and `test_the_output_file_is_the_v1_envelope` failed on the committed tree (found by running the suite after the commit, not before). Fix: `.prettierignore` now excludes `mcd*/fixtures/*.json` and `mcd*/mcd*_output.json`; the five JSON files were regenerated with the documented `write_fixtures()` command (each parses equal to the committed version, only the layout returned); the two `.source.md` files keep their prettier-formatted layout; the local, unpushed commit was amended. The first commit (`af54e3c9`) exists only in the reflog. The same ignore covers `mcd1/` and `mcd3/`. Rule for every later session: run the tests again **after** the commit.
- **MCD1 has no override.** The "with an override" rows of the baseline restrict the legacy module's candidate list to one indicator (what an override would do), in a scratch script. The legacy evaluator is byte-identical.
- **Do not run `legacy/mcd1_evaluator.py` as a script or call `run_mcd1_test`:** it writes `mcd1_output.json` next to itself and would change the history copy. Only the class and the tests are used.
- **v4 becomes readable.** The legacy evaluator fails on v4 without an override (`non_a` and `non_b` both populated); with the setting `non_b` the reading is VALID and `non_a` goes to `populated_candidates` (D3). With `non_a` set, v4 is a real SIDEWAYS cycle (`MCD1_SIDEWAYS_LOWER_BREAKDOWN`).
- **Three of nine states have real examples**, each on a different cycle (plan §5). The other six are synthetic.
- **The legacy classified on a CP already rounded to 4 decimals and an 80% share rounded to 2 decimals.** The retrofit decides on prices and exact counts (`100 × count ≥ 80 × N`); the two forms are equivalent for every window that can occur, except when Close is within 0.00005 of a band (plan §6).
- **The registry has `bias: DAVIN` on six states on purpose.** The shared register checks in P3 will not pass until Davin's D6 answer replaces them. This is the gate that keeps the builder from inventing bias.
- **`concept/` is not created for MCD1** (no board; git cannot hold an empty folder). The folder-layout test in P3 must allow its absence.
- **The three tier helpers MCD2 added on top of the kit** will now exist in two evaluators; moving them into the kit is a kit change (plan §7).
- **Inherited and unverified:** the statistics' fit windows may include the still-open bar (`.claude/state/waiting-on.md`). MCD1 reads `regression_angle`, `containment_rate` and `containment_n` from those fits, and `N_micro` depends on the last. Settle it before certification.
- `git stash list` holds 17 old "lint-staged automatic backup" stashes (3 to 5 weeks old) and one `session-2-4-wip-checkpoint`. Not from this session; untouched.
- Every `git` call warns "LF will be replaced by CRLF" (`core.autocrlf=true`); the new files are LF (checked with Python). Two of the
  originals (`mcd1_output.json`, `test_mcd1_unit_tests.py`) are CRLF in the working tree, so their `legacy/` copies are too (byte-identical on disk).
