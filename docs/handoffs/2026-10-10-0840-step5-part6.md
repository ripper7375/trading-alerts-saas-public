## 6. Decisions for Davin (readings of mine where the order or the architecture was silent)

Built as the default unless you say otherwise.

1. **Shapes and names.** All four routes take JSON; `offer`, `size` and `consent` are POST (the order did not say; `offer` has a body and no side effect, so GET with a query string was possible). The cycle is `cycleSlot` (camelCase like the engine's `pinnedSlot`, not `cycle_slot`): required for `size` and `consent`, optional for `offer` (without it the newest reading is the pinned one and the answer names it). Unknown fields are ignored, not refused: refusing them would tell an attacker what is read.
2. **The order of refusal: flag (404 for everybody), session (401), tier (403).** A switched-off feature is not discoverable. A missing or unknown tier counts as Free.
3. **The consent route requires `shownSetupSha256` and refuses (409 `SETUP_CHANGED`) a setup that is not the one shown.** The order says the server recomputes from the cycle, the zone and the inputs; it does not say the record must be the setup the trader saw. Because the picture moves (a release enters the window, the broker row ages, a newer cycle arrives), a recomputed record could differ from the screen. The `size` route returns `setupSha256`; the buttons send it back. If you prefer to record whatever the server computes at the press, drop the field and the comparison (two lines in `handlers.ts`); the hash would still be in the record.
