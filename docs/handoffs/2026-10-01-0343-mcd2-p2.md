## 7. Problems and surprises the next session must know

- **D6 applied as written to all nine states.** The board supports it (the price is "still assumed to continue with the original trend"). One consequence, recorded in spec §9 and not a question: in `MCD2_UP_UPPER_BREAKOUT` and `MCD2_DOWN_LOWER_BREAKDOWN` the draft synthesis rule 2 ("bias against the spike") will differ from the sensor's own bias. Allowed by ADR-025.
- **The kit does not check `regression_angle`.** `statistics_check` tests the row and the containment rate only, so MCD2 adds an angle-is-a-number check in tier 4 and the ±90 bound in tier 3 (plan §4).
- **The classification changes slightly:** legacy classified on a CP already rounded to 4 decimals; the retrofit compares prices (standard §11.2). The difference only appears when the metric is within 0.00005 of a band (plan §6).
- **All four real cycles are `IN_CORRIDOR`.** The six outside-corridor states and the three sideways states have no real-data example in v1 or v4, so T1 uses synthetic bundles. The untracked replica batches (v2, v3, `engine-1-5-new2` to `4`) were not scanned; if Davin wants a real outside-corridor or sideways cycle as a fixture, one of them may hold it.
- **The baseline table lives in plan §6**, not in a manifest draft: the manifest is rewritten in P3 (R9), so P3 should carry the table into it.
- **The legacy evaluator is not runnable from `legacy/` as a CLI** (its `main()` resolves the workbook one folder up). Only its class and the tests are used. It was left byte-identical on purpose.
- **Inherited, unverified:** the statistics' fit windows may include the still-open bar (`.claude/state/waiting-on.md`). MCD2 reads `regression_angle` and `containment_rate` from those fits. Settle it before certification (stage 5); it does not block P3.
