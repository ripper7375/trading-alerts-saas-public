## 3. Security and guard isolation

- **Both flags default to false, strictly.** `lib/intake/server/flags.ts`: `isIntakeEnabled` is `env['INTAKE_ENABLED'] === 'true'` and `isInstantPromptsEnabled` is `env['INTAKE_INSTANT_PROMPTS_ENABLED'] === 'true'`; unset, empty, `TRUE`, `1` and `" true"` are off (the wiring test names seven spellings for the second). **Neither variable is set anywhere**: `git grep` finds them only in code that reads them, in tests and in documents; no `.env*`, workflow, `vercel.json`, Railway file or Dockerfile mentions `INTAKE_`. The browser never sees either variable (the pages read the flag on the server and pass a boolean down).
- **`__tests__/lib/intake/boundaries.test.ts` passes (51 tests), but it is not the equity guard (F4).** It is the import and purity guard of `lib/intake` (no `fetch`, `process`, `Date`, `window`; only the files named in `ALLOWED_IMPORTERS` may import it; I updated its comment, not its rules). **The "no equity, no commission" check lives elsewhere and passes:** `lib/intake/packet.ts:125` (`FORBIDDEN_PACKET_KEY = /equity|commission/i`: a packet with such a key at any depth is refused), `read/profile.test.ts` (18: the profile is a six-field projection, never the equity or the commission, whatever the stored profile holds) and `pipeline-golden.test.ts:233-236` (`JSON.stringify(packet)` of **each of the 288 golden packets** must not match `/equity|commission/i`). **"Balance" is not a forbidden word:** "account balance" is a glossary synonym for the term `equity` (`config/intake/glossary.v1.json`), not a key, and no packet field or test scans for it; the equity balance itself is the thing `equity` names. If you want the word scanned too, it is a one-line change to the two regexes.
