## 6. Decisions for Davin (readings of mine where the order or the architecture was silent)

Built as the default unless you say otherwise.

1. **Money is shown as unconverted US dollars through `formatChargedAmount`, not `formatCurrency()`.** The policy (`docs/policies/08-locale-i18n-compliance.md` section 4) says `formatCurrency()` is convert-and-format and that it drops the decimals above 1,000: it would turn the trader's exact $68.28 risk into a rounded figure in another currency. The account is in dollars, so the report shows "US$75.00" or "75,00 $" in the viewer's own digits, and gold's price (a quote in dollars an ounce, not an amount of money) as a plain number. `Number()` appears in one file, `components/report2/format.ts`, between text that is already rounded for display and `Intl`; no money maths passes through it. If the product should show the viewer's currency, that is a decision about what the report promises (the trader's risk is a figure in the account's currency).
2. **The two version strings moved and changed.** `REPORT2_TEMPLATE_VERSION` and `REPORT2_DISCLAIMER_VERSION` now live in `lib/engine4/templates/report2.ts` as `report2-template/draft-1` and `disclaimer/draft-1`, so the version a consent record names is the version of the template that drew the report. The part 6 file re-exports them; two pinned tests changed. A record keeps the string it was written with (nothing is recorded in production: the flag is off). Any change to the template's text or layout bumps the template version.
3. **A custom entry has no list of structural stops, only a custom stop.** The modal definition holds stop options per pill, because the options depend on the entry (their distances, and which levels qualify); for an entry of the trader's own the validator computes them for its check 2 but the `size` answer does not carry them. The modal therefore offers "Custom stop" (pre-filled with the distance the trader had, at least their Min SLD) and the server still recognises a typed distance that equals a structural option. I did not guess a list from the pills' options (it would miss levels). The fix is small and yours to order: export the validator's choice of stop options and add `stopChoices` to the `size` answer.
4. **The swap is not shown.** The plan's part 7 lists "the swap for a Day Trader that can cross the rollover". The broker row is read with `swapLong`, `swapShort` and `swapMode`, but nothing hands them to the setup: `ValidatedSetup` has no swap field. Showing it means a server change and a money decision of yours (the sign, the unit `swap_mode` names, and what "can cross the rollover" means for a holding window). The spread used is shown, with the commission.
5. **The calendar's age is not shown.** A calendar not exported for 45 minutes still blocks, and 6.6 wants its age shown. The age is in the offer answer's `blackout`; the card takes the blackout only to name the release behind a refusal. A small follow-up when the chat caller exists.
6. **The consent bar tracks an id per (action, setup hash), kept until the outcome is known.** A press that got no answer is repeated with the SAME id (so a record that was written is returned, not written twice), even if the trader pressed another button in between; a definitive answer, or a different setup, gets a new id. This was a design gap I found while writing the test for it: my first version remembered only the latest attempt. The Redis guard still fails open when Redis is down (part 6 reading 4); the id tracking is the browser's half.
7. **The modal asks the server to size every settled set of fields, even an incomplete or invalid one**, not only the good ones: Modify and Decline record what was shown, and they need the hash of a setup the server has seen. The prechecks only give instant messages; they never decide, and an empty field waits instead of shouting. A size call is debounced 250 ms and an answer for figures the trader has already changed is thrown away.
8. **The translations are my drafts.** 177 keys in 17 languages, written carefully (the same placeholders, the language's own script, its usual trading terms), checked by tests for completeness and shape, **not read by anyone who speaks the language**. The nine texts of `DRAFT_TEXT_KEYS` (the three compulsory notices, the three buttons, the three outcomes) are the ones counsel replaces; the rest should get a native read before the flag goes on. In Urdu and Arabic the figures inside sentences are wrapped in direction isolates so a price or a level name cannot be reordered.
9. **The allowed range of a custom entry is shown rounded INWARD** (the low end up, the high end down, to two places): the exact bounds are often half-cents (4,282.525 to 4,427.425 on 18 Sep), and rounding to the nearest printed an edge that the check refuses. Found in the browser.
10. **A figure in a sentence is a placeholder, never a number written into 19 texts.** The repo's own guard (`systemconfig-figures-guard.test.ts`) refused "more than 5% from the live price" in a dictionary, and rightly: the 5% is the engine's entry typo filter (`ENTRY_TYPO_FRACTION`), so the text now says `{limit}` and the message fills it from that constant. A new test keeps every report text free of a figure of its own.
11. **The preview route is for local development only.** It 404s under `NODE_ENV=production` (which includes Vercel previews), its server actions refuse, its world reads the stored goldens from the repository by `process.cwd()`, and it sits under `app/dev`, which the existing compulsory-pages rule already excludes. Its broker row, Tier-1 ids and M5 bars are the same TEST values the tests use, labelled so.

Open points: **(a)** readings 3 and 4 are server changes if you want them; **(b)** the wording and the translations (reading 8, D14); **(c)** whether to run a mutation pass on part 7; **(d)** D13 and the carried list in section 5.
