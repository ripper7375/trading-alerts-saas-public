   pending migrations, so it can be applied alone: `prisma db execute --file prisma/migrations/20261002000000_add_cycle_pipeline_tables/migration.sql`, then
   `prisma migrate resolve --applied 20261002000000_add_cycle_pipeline_tables`. It must be applied before any gateway deploy that writes these tables (parts 4, 6, 8, 9).

Information, no decision needed:

- **The seed rows use `effective_slot` 0**, meaning "the ADR-010 starting values apply from the beginning". Every slot therefore resolves to a setting, so the resolver in part 6 has no "no setting" case.
  The cost: a replay of a slot older than the setting's real first use would report that setting.
- The setting's setter (part 6) must refuse an `effective_slot` that is not later than the current slot, otherwise a row added afterwards would change a replay. The table cannot enforce this; it is in the model's comment.

## 7. Problems and surprises the next session must know

1. **Part 3 must take the export time from the file's modification time, not from the "Export Time" line.** That line (`ohlcvexportlightweight_v2_29.mq5:499`, written when `InpIncludeMetadata` is on) is `TimeCurrent()`:
   the last tick's broker server time, not UTC, and on a quiet market it lags the write. The repo's sample exports carry no such header at all. `m5_export_at` and `m15_export_at` are documented that way in the schema.
   This sharpens the earlier instrumentation decision: the manifest records the file's write time and the newest bar's open time.
2. **If Parts 3 or 4 need a column this migration lacks, amend the migration in place while it is unapplied; once Davin has applied it, add a second migration instead.** The columns beyond the plan's list
   (`backlog_rows`, `repush_rows_unsent`, `check_detail`, `state`, per-timeframe export and bar fields) are my reading of the manifest as planned, before Part 3 fixes it.
3. **Docker's engine is not running on this machine** (`dockerDesktopLinuxEngine` pipe missing), so the plan's "replay on `postgres:16-alpine`" was done on Prisma's embedded Postgres instead. It is a real
   Postgres-compatible engine (PGlite), so it exercises syntax, constraints, defaults and introspection; it is not the Postgres 16 server production runs, so a final check on a real server remains
   Davin's, as for every migration.
4. **`prisma migrate diff --script` prints two dotenv lines on stdout in this repo**, so a redirect starts with `◇ injected env`. They were stripped from the migration. Also `--from-url` was removed in Prisma 7.
   Both are in `database-traps.md`.
5. **The stubs file only ever held `MarketDataV6` among the market models** (point-in-time, statistics, events and the currency tables were never added). The four new interfaces follow the instruction and the
   `MarketDataV6` precedent; the older gap is pre-existing and left alone. `schema-sync.spec.ts` now checks the four new interfaces and delegates against the schema, so these cannot drift silently.
6. **One test-writing trap, fixed in my tests:** reading a model's raw body and searching it for `@updatedAt` also matches a comment saying "No @updatedAt". The new tests inspect comment-stripped declarations.
   The older invariants for `IndicatorStatistic` and `EconomicEvent` still scan the raw body and pass only because their comments avoid that phrase; left as they are.
7. A repo-wide `grep` for a file name ran past two minutes and had to be stopped (the known slowness in `environment-gotchas.md`); later searches named their folders.
