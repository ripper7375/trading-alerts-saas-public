- **`chat-state.ts`** is the reducer, pure: the items on screen (the trader's bubble, a reply, a refusal, an error, a note that the trader stopped it), the request in flight and its six stages (`PENDING`, `STARTED`, `DONE`, `SKIPPED`), the thread, the state of the state route. - **`use-chat-stream.ts` and `chat-provider.tsx`:** one request at a time, guarded on a REF (two Enters and a click in the same tick send one request); the body is exactly `{ client_request_id, thread_id?, question | kind }`; `Try again` re-sends the same `client_request_id`; unmounting aborts the request and nothing is drawn after; the balance is read again after every request that ended (not after a route that is off); a Free trader's provider never calls a route. `ChatPanel` mounts its own provider unless one is already above it, so part 9 can hoist one without touching the panel.

## 5. How it works (for the approval)

**One question, in order.** The composer calls `ask`; the provider refuses an empty, blank or over-500 question and a second request in the same tick; the reducer shows the trader's bubble and starts six waiting stages; `sendMessage` posts `{ client_request_id, thread_id?, question }`; each stage event moves one stage; the one terminal event becomes a card (`result`), a refusal card (`refusal`, or a JSON body with a status and the balance) or an error card (`error`, or a failure on the way); the thread of the reply is kept so the next question joins it; the balance is read again. The whole reply arrives at once (D24): nothing is drawn token by token and nothing is retracted.

**What the panel never does.** It sends no user id, tier, language, model, symbol or equity (a test reads the body); it adds no number, direction or disclaimer of its own (the direction, the figures, the stamp and the disclaimer VERSION are the server's, the disclaimer's TEXT is the interface's own, in the reader's language); it never prints a number of units or tokens; it never translates an id.

**The states of the state route.** Not switched on (404): "The AI Analyst is not switched on yet", no composer and no meter. Failed: a notice with "Try again" and the composer stays. Loading: one line. Ready: the badges, the picker, the meter, the composer.

**Free.** No chat at all (ADR-072): the header's picker is a link to `/pricing`, the body is the recorded example under a banner that cannot be missed, the footer is "Read-only (Free tier)" with the upgrade button. The renderer is tested here on a fixture recording; the recording is part 10's content.

## 6. Decisions and readings of mine

1. **The picker is display-only today.** The message route takes no model (part 7), so the selection changes what "analyses left" divides by and nothing the server does. No model has passed, so the picker says "No model available yet". When the server learns to take a model, the provider's `modelSlug` is what to send. **Nothing is chosen for the trader behind their back, and nothing is sent that the server would ignore.**
2. **Cost is shown as "about N analyses left", not as units.** A unit is a micro-dollar of the gateway's cost (§7.3); printing it would publish the business's own cost, and ADR-073 says no token number is published until the first measurement run. The picker shows the count per model; the meter shows the share and the count; the refusal shows the share. A test fails if a raw unit appears.
3. **A conversation survives nothing yet:** collapsing the panel unmounts it (section 7, item 3).
4. **"Open trade setup" on a Report 1 is built from the report** (`Report1Result` has no action field): the cycle slot of the stamp, the trader type of the direction and the zone ids of the report, and only for a LONG or SHORT reading with zones and a cycle (never for stand aside or neutral). The button asks Engine 4's `offer` route for that cycle (not the newest) and opens the existing Trade Setup modal with the pills of the zones the report names (all open zones when none of them is open); not offered shows Report 2's own reason; any failure, including the route being off, is one sentence. A short answer or the action card uses the action the server sent.
5. **"Try again" is offered only when the same request may be sent again:** the server says so for an error event; the browser says so for a dropped connection, a cut stream and a 5xx. A 4xx is not retryable.
6. **A new reply scrolls to its TOP**, a question and the stages scroll to the bottom: a report's headline and direction come first.
7. **The composer is disabled while a request is in flight** (as ordered) and gets the cursor back when it ends; Stop is on the progress list only (one Stop, not two).
8. **A refusal's allowance line is a share, rounded down to a whole percent** ("0%" for a balance of 0.15%).
9. **The disclaimer text, the "written by AI" notice and the seven reasons of the fixed answer are my English drafts** (counsel, ADR-098 D14); the disclaimer version string is the server's.
10. **The meter, when the allowance is not set, says so and draws no bar; when it cannot be read, a dash.** Neither is a made-up bar.
11. **The picker is a native `<select>`** (works with a keyboard, a screen reader and a phone's own picker at 320 px), at the cost of one line of text per option.

## 8. Problems and surprises

1. **The wire needed its own light validator.** The strict contract validators sit on the intake pipeline and `node:crypto`, so the browser cannot import them; `wire.ts` checks only what the panel needs (a known kind and the fields it reads), and the fixtures test runs the strict validators over every recorded stream so the server's contract and the browser's reading cannot drift apart unseen.
2. **The first recorded "allowance refused" answer was a mis-sized allowance** (available equal to the limit, but "used up" in words). It was re-recorded by spending the ledger to what a trader who had asked all month would have left, so the card shows a share of 0%.
3. **`compulsory-translation-coverage.test.ts` failed (six languages)** for two reasons that are the tool's rules, not the panel's words: it counts any string literal in the import closure of `/terminal` and `/free` that equals an existing dictionary key as used, and the Trade Setup modal's imports (`lib/engine4`, with a literal `"events"`) and my registry's `'Channel'` put two old English copies in reach. I translated them (they were `Channel` and `events`: `ar`, `fr`, `it`, `ko`, `zh`, `zh-TW`). Separately, `'{count} / {max}'` failed every language because the tool reads placeholder names as words; the counter is now built in code, not a key.
4. **The dev server could not load a language's dictionary in the browser pane** (`experimental.turbopackLazyDynamicImports` in `next.config.js`: the lazy chunk answers 404 and the provider falls back to English). To see the translated screens I set the flag to `false`, restarted, looked, and restored `next.config.js` and `next-env.d.ts` with `git checkout`. It is an environment limit, not the panel's code (Jest loads all 19). Recorded in the gotchas file.
5. **The browser pane's screenshots lag one change behind a script**, and a right-to-left page puts the frame on the right; both cost me captures (gotchas file).
6. **A test that waits for `<html lang>` is too early for a non-bundled language:** the attribute changes before the dictionary arrives. The RTL tests wait for a word of the language.
7. **The shell collapsed backslashes and nested quotes in `node -e` and heredocs again;** every patch was written to a file in the scratchpad with the Write tool and run with Node.
