### What one `cycle-ready` job does, and what each way out does

| Event                                                                                          | What the worker does                                                                                                                     | Rows written                                                                   |
| ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Job malformed (no data, another symbol, slot off the grid, no `readyAt`)                       | Discards the job (no retry mends it), throws                                                                                             | none                                                                           |
| Job announced more than `SENSOR_MAX_JOB_AGE_SECONDS` (600) ago                                 | Skips it; the outcome `SKIPPED_OLD` with the age is the job's result and a log line. Nothing is read. Drains the backlog without a read  | none                                                                           |
| READY row not there yet (`CYCLE_NOT_READY`), attempts remain                                   | Throws on purpose; Bull retries with its back-off                                                                                        | none                                                                           |
| Same, on the **last** attempt                                                                  | Runs a STALE bundle through the runner                                                                                                   | one STALE row per enabled MCD (`DATA_STALE`) + the stale bundle                |
| READY row untrustworthy or its tuning unreadable (`INVALID_CYCLE_ROW`)                         | Same, at once (it will not mend by waiting)                                                                                              | STALE rows                                                                     |
| Cycle loaded                                                                                   | Runs the loader's bundle; warns if the job's `retuning` differs from the row's (the row is used)                                         | one row per enabled MCD, **INVALID and STALE readings included**, + the bundle |
| Every MCD `off` in the worker configuration (the committed file)                               | Runs the runner, writes nothing (`NOTHING_ENABLED`): no reading exists to replay                                                         | none                                                                           |
| Runner failed (no Python, timeout, refused request, crash, output not a result)                | Fails the job; discards it only when a retry cannot help (missing interpreter, refused request, unusable output). **Invents no reading** | none                                                                           |
| Writer refuses the cycle (an envelope breaks `mcd-output/1`, wrong MCD or slot, hash mismatch) | Discards the job, throws                                                                                                                 | none (refused before the database)                                             |
| Database failure                                                                               | Fails the job (Bull retries); the transaction leaves nothing half-written                                                                | none                                                                           |
| Same cycle delivered twice                                                                     | `skipDuplicates`: adds nothing, and the old bundles are still cleaned                                                                    | none new                                                                       |

`SENSOR_RETUNING_ENFORCED` defaults to **false** (RETUNING is read from the READY row and recorded as `retuning_observed`; applied, and then recorded as `retuning_applied`, only when it is exactly `true`). `SENSOR_WORKER_CONFIG` is the optional override of the committed `worker_config.yaml` you allowed in part 1 (rollback or rehearsal without a deploy).

1. **Where a skipped job is recorded.** Built: the job's **return value** (`SKIPPED_OLD`, the slot, the age, the bound), which Bull keeps for the last 100 completed jobs (`removeOnComplete: 100`), and a warning in the log. No table. Part 7's kit would count skipped jobs by reading Bull or the log, not SQL. Options: **keep (recommended, no migration)**; or a small `sensor_job_log` table (one more migration file, unapplied, and one more write per skip).
2. **The reading of a cycle the worker cannot load.** Built: a STALE bundle through the runner, so every enabled MCD answers STALE with the kit's existing reason **`DATA_STALE`** (rule 7), both when the READY row never appears after three attempts and when it cannot be trusted. Options: **keep (recommended: no kit change, no new reason code)**; or a reason of its own (for example `CYCLE_NOT_LOADED`), which is a MINOR kit change in `reason_codes.py`, the standard and every registry, and a new statistics series.
3. **Every MCD off writes nothing.** With the committed `worker_config.yaml` the runner runs and returns no reading; the worker writes no row and no bundle (`NOTHING_ENABLED`), so enabling the module before any flag is turned on fills nothing. Options: **keep**; or store the bundle anyway (a bundle with no reading to replay, about 1.1 to 2.7 GB for 90 days).
4. **The retry window before STALE.** `cycle-ready` jobs carry `LANE_JOB_OPTIONS` (set in step 2's `cycle-manifest.service.ts`): three attempts, exponential back-off from 2 s. Bull's formula is `(2^n - 1) x delay`, so the worker waits **2 s and then 6 s** (about 8 s) and writes STALE on the third attempt. The job is announced just before the row commits (milliseconds), so that is ample for the expected race. The honest limit: once STALE rows are written for a slot, rows are append-only, so a READY row that appears later (a commit that failed after the announcement and succeeded on the manifest's own retry) is **never evaluated**. Options: **keep (recommended)**; or a longer window (a change to step 2's queue options, not to this part), or re-announce when the row appears (step 2 code).

## 7. Problems and surprises the next session must know

In a handler `job.attemptsMade` is the attempts made BEFORE this one; Bull increments it in `moveToFailed`; `job.discard()` stops further retries. **No real Redis was used** (Docker's engine is still not running): the retry rule is shown on a fake queue that follows Bull's source, and the Bull explorer's registration is shown with a fake queue in a real Nest graph. A real queue is first exercised in B1.
2. **Ajv `strictTypes` refuses the kit's schema** (decision 7).
3. **A gated test of part 2 depends on the planner's statistics of an empty table.** `sensor-tables.pg.spec.ts`, "the retention delete is served by the cycle_slot index", passed on part 2's fresh database and **failed here, deterministically, once the table had held and lost rows** (`reltuples` 0; on a table never used it is -1): with two usable indexes and no statistics the planner chose `market_cycle_inputs_symbol_cycle_slot_key` for `cycle_slot < 1`.
