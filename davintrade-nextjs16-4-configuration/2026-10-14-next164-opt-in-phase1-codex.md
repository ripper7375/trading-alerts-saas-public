### Static-route guard prerequisites

Installed [ensureStatic docs](../node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/02-route-segment-config/ensureStatic.md)
require `cacheComponents: true`. Guards cover the route's parent layouts.
Current `app/layout.tsx` reads `getServerAppearance()`, cookies, headers and
`getDisplayUsdRates()`. Appearance reads the session and user database.

All five target pages are Client Components under
`app/(marketing)/{pricing,about,terms,privacy,disclaimer}/page.tsx`.
A server wrapper/layout can export the guard, but cannot remove request-bound
parent behavior. Do not move locale/theme/auth code without an approved design
that addresses initial paint and existing behavior. Begin with terms/privacy/
disclaimer after the parent-layout prerequisite is resolved; pricing includes
commercial display behavior and needs its own acceptance criteria.

Cache Components changes the application rendering model. Current inventory found 13
page/layout and 25 API `force-dynamic` exports; audit handlers separately rather
than assuming identical page and API behavior. New adoption should explicitly
choose `partialPrefetching: true` as recommended by the installed migration
and config docs; an unset value warns. Test Suspense boundaries and unsupported
segment options across the application before calling this a route-only pilot.

### React and caching corrections

React/React DOM 19.3 exposes `ViewTransition`, but installed React typings are
18.x and omit it. The roadmap timeframe example never renders a transition
boundary. `startTransition` alone does not supply that boundary. Alert-list
updates must also occur in a supported transition, with CSS for custom names.
The live chart is canvas-driven with effect-based updates, so a settings-tab
or DOM-list pilot is a better first validation target. The proposed alert feed
paths are illustrative rather than existing files. Verify browser feature
support and reduced motion; the roadmap's Chromium 111+ claim is too broad.

`browser()` belongs to `react-dom` and is used as `use(browser(...))` under
Suspense to defer browser-only content; it is not browser detection. Fragment
refs expose a FragmentInstance, not an HTMLElement, and require explicit
`<Fragment ref={...}>`. Both optional APIs also lack installed React 18 type
support and require no Phase 1 flag. Keep indexed legal/marketing copy outside
browser-only fallback boundaries.

The default `use cache` storage is an in-memory LRU, with no guarantee of
sharing across serverless instances or deployments. The real economic-events
route is authenticated and PRO-gated. Cache a shared read helper after access
checks, with a concrete freshness/invalidation policy; do not cache the whole
user response. `navigation()` needs Cache Components and a Suspense boundary;
partial prefetch behavior must be understood before promising skipped queries.
