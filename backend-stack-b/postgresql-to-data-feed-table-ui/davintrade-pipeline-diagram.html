WebSocket Channel — "feed_row" Event
A persistent Socket.IO connection is maintained between Next.js frontend and NestJS gateway. When NestJS emits "feed_row", the payload travels over this connection without HTTP overhead — no polling, no page reload.

Payload structure per event: { timestamp, symbol, tf, close, impHigh, impLow, highLowRej, tcP1, tcP2, tcP3, tcB1, tcB2, tcB3, srP1 }

Next.js 16 — WebSocket Client Hook
A custom useDataFeed() hook manages the Socket.IO client lifecycle. On receiving "feed_row", it prepends the new row to the top of the table state array and triggers a React re-render. The auto-scroll logic detects the state change and smoothly scrolls the table to the newest row.

End-to-End Timing & Key Numbers
Data Cadence
5 min
New PostgreSQL row inserted every M15 candle close. Flask ingestion service writes indicators + signals.
DB → NestJS
<100ms
pg_notify fires immediately on INSERT. NestJS LISTEN picks up event and queries the new row.
NestJS → Client
<50ms
Socket.IO emit over persistent WSS connection. No HTTP handshake overhead.
Client Render
~16ms
React state update + one DOM paint cycle. Row appears highlighted in green, table auto-scrolls.
Total E2E
<200ms
From PostgreSQL INSERT to new row visible on user screen. Well within the 5-min data window.
