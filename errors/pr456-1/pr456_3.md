The **Secrets scan** job is failing because it detected potential hardcoded secrets in your codebase. The workflow scans for:

- Stripe live keys (`sk_live_*`)
- AWS keys (`AKIA*`)
- GitHub tokens (`ghp_*`)

### Steps to Fix

**1. Identify the hardcoded secrets:**

Run these commands locally to find the exact locations:

```bash
# Check for Stripe keys
grep -rE "sk_live_[A-Za-z0-9]{20,}" --include="*.ts" --include="*.tsx" --include="*.js" --exclude-dir=node_modules --exclude-dir=.next .

# Check for AWS keys
grep -rE "AKIA[A-Z0-9]{16}" --include="*.ts" --include="*.tsx" --include="*.js" --exclude-dir=node_modules --exclude-dir=.next .

# Check for GitHub tokens
grep -rE "ghp_[A-Za-z0-9]{36}" --include="*.ts" --include="*.tsx" --include="*.js" --exclude-dir=node_modules --exclude-dir=.next .
```

**2. Replace hardcoded secrets with environment variables:**

```typescript
// ❌ BEFORE - Hardcoded secret
const stripeKey = 'sk_live_abc123...';

// ✅ AFTER - Use environment variable
const stripeKey = process.env.STRIPE_SECRET_KEY;
```

**3. Add secrets to your environment:**

Add the actual values to:

- `.env.local` (for local development - ensure this file is in `.gitignore`)
- GitHub Secrets (for CI/CD): Settings → Secrets and variables → Actions

**4. Revoke compromised secrets:**

If these secrets were committed to the repository, they are compromised and must be revoked/regenerated in their respective platforms (Stripe, AWS, GitHub).

Once you remove the hardcoded secrets and use environment variables instead, the security check will pass.
