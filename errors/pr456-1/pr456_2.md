The job is failing because the secrets detection is finding the pattern "AKIA" (AWS key prefix) in **ECharts GeoJSON map data files**, not actual AWS credentials. This is a false positive.

Looking at the files flagged:

- `seed-code/echarts/test/data/map/js/province/heilongjiang.js` - contains coordinate data like `"@@LKT]LEL@HB|VX@TOJ...AKIA..."`
- `seed-code/echarts/test/data/map/js/province/fujian.js` - similar GeoJSON data

These are legitimate test data files from the Apache ECharts library containing encoded geographic coordinates.

### Fix: Exclude Test Data from Secrets Scan

Update the secrets scan step in `.github/workflows/security-checks.yml` to exclude the seed-code directory:

```yaml
# Lines 100-104
# AWS keys
if grep -rE "AKIA[A-Z0-9]{16}" --include="*.ts" --include="*.tsx" --include="*.js" --exclude-dir=node_modules --exclude-dir=.next --exclude-dir=seed-code .; then
echo "❌ Found potential AWS key"
FOUND=1
fi
```

Apply the same exclusion to the other secret patterns (Stripe and GitHub):

# Lines 95-110
