- Could not locate module '@/lib/cache/indicator-cache'

**Root Cause:**  
Your tests and code are using path aliases (e.g., @/lib/...), but Jest is not configured to resolve these aliases. This is a common issue when using TypeScript/Next.js or similar setups where tsconfig.json (or jsconfig.json) defines aliases, but Jest needs its own configuration to recognize them.

---

## Solution

**1. Sync jest.config.js (or jest.config.ts) with your tsconfig.json path aliases**

Install `jest-module-alias` plugin or use the built-in `moduleNameMapper` config.

**If using `ts-jest`:**  
Add (or update) the `moduleNameMapper` field in your jest config:

```js
// jest.config.js
module.exports = {
  // ... other config ...
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/src/$1', // adjust 'src' to your baseUrl if needed
  },
};
```

- If your project root alias "@/..." points to "src", replace `src/` as appropriate.
- For multiple aliases, add more entries.

**2. Make sure the target folders/files exist**

Some logs indicate tests trying to import files that may not exist. Double-check paths or typos in:

- **tests**/lib/admin/code-distribution.test.ts
- **tests**/lib/cron/monthly-distribution.test.ts
- **tests**/lib/affiliate/code-generator.test.ts
- **tests**/api/cache/stats.test.ts
- **tests**/lib/jobs/alert-checker.test.ts

**3. Verify `tsconfig.json` and `jest.config.js` are consistent**

Example for `tsconfig.json`:

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"] // adjust as needed
    }
  }
}
```

Your `jest.config.js` and `tsconfig.json` must match in their understanding of the alias.

**4. Re-run the tests:**  
After making these changes, your tests should run successfully.
