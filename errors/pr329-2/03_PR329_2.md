The build is failing because Next.js is running with Turbopack enabled, but your `next.config.js` has a `webpack` configuration without a corresponding `turbopack` configuration. This creates a conflict.

### Fix: Add Turbopack Configuration

Add an empty `turbopack` configuration to your `next.config.js` file to silence this error. Since the webpack config is only doing basic fallback setup and external package exclusions, an empty Turbopack config should work fine.

**Update `next.config.js` (and `frontend/next.config.js` if applicable):**

```javascript
/** @type {import('next').NextConfig} */
const nextConfig = {
  // Enable React strict mode for better development experience
  reactStrictMode: true,

  // Modular imports for better tree-shaking of icon libraries
  modularizeImports: {
    'lucide-react': {
      transform: 'lucide-react/dist/esm/icons/{{kebabCase member}}',
    },
  },

  // ... rest of your config ...

  // Experimental features for Next.js 15
  experimental: {
    // Enable server actions (stable in Next.js 15)
    serverActions: {
      bodySizeLimit: '2mb',
    },
  },

  // Add this to silence the Turbopack warning
  turbopack: {},

  // ... rest of your config including webpack, headers, etc ...
};
```

Add the `turbopack: {}` line after the `experimental` section (around line 53) and before your production optimizations.

This tells Next.js that you're aware of Turbopack and have intentionally configured it (even if empty). The webpack configuration will still be used when webpack is the bundler, and Turbopack will use its defaults when enabled.
