The build is failing because it's using **Turbopack** (Next.js's new bundler) but your configuration only has a `webpack` config without a corresponding `turbopack` config. This causes Next.js to error out as a safety check.

### Fix

Add an empty `turbopack: {}` configuration to your `next.config.js` files. This explicitly tells Next.js to use Turbopack and silences the error.

**For `next.config.js` (root):**

```javascript
/** @type {import('next').NextConfig} */
const nextConfig = {
  // Enable React strict mode for better development experience
  reactStrictMode: true,

  // Add this configuration
  turbopack: {},

  // Modular imports for better tree-shaking of icon libraries
  modularizeImports: {
    'lucide-react': {
      transform: 'lucide-react/dist/esm/icons/{{kebabCase member}}',
    },
  },
  // ... rest of your config
```

**For `frontend/next.config.js`:**

```javascript
/** @type {import('next').NextConfig} */
const nextConfig = {
  // Enable React strict mode for better development experience
  reactStrictMode: true,

  // Add this configuration
  turbopack: {},

  // Modular imports for better tree-shaking of icon libraries
  modularizeImports: {
    'lucide-react': {
      transform: 'lucide-react/dist/esm/icons/{{kebabCase member}}',
    },
  },
  // ... rest of your config
```

Add the `turbopack: {}` line after `reactStrictMode: true` (around line 11) in both files. This tells Next.js you intentionally want to use Turbopack, and the webpack configuration will be ignored. Most applications work fine with Turbopack without additional configuration.
