The failing job reports two distinct issues:

1. Redis cache clearing is failing with the error: [Redis] Invalidate pattern error: Error: Connection is closed. This happens during calls to clearAllCache and invalidatePattern in lib/cache/redis.ts and lib/cache/indicator-cache.ts.
2. The test GET /api/indicators/[symbol]/[timeframe] fails with: error: 'Query timeout exceeded', indicating a downstream database fetch or proxy timeout from the indicators API endpoint.

**Root cause and solution:**

### 1. Redis Invalidate Pattern Error

The error occurs at:

```typescript
110 | console.error('[Redis] Invalidate pattern error:', error);
```

This suggests that getRedisClient() is returning a closed client or Redis became unavailable during the test execution.

**Solution:**

- Ensure Redis is up/running and connection parameters are correct in your environment.
- Optionally, modify your Redis wrapper to check and (re)connect if the client is closed before running commands:

```typescript
// In lib/cache/redis.ts and similar frontend file:
export async function getRedisClientSafe() {
  const redis = getRedisClient();
  if (!(await isRedisConnected())) {
    await redis.connect(); // ioredis supports .connect()
  }
  return redis;
}

// Then use getRedisClientSafe() instead of getRedisClient()
```

- Alternatively, update all Redis actions to use isRedisAvailable() before mutating actions.

### 2. "Query timeout exceeded" from GET /api/indicators/[symbol]/[timeframe]

This trace and error comes from app/api/indicators/[symbol]/[timeframe]/route.ts and is handled in your try/catch block:

```typescript
295|       error: error instanceof Error ? error.message : 'Unknown error',
...
315|               'Unable to connect to the database. Please try again in a few moments.',
```

**Solution:**

- The timeout indicates your PostgreSQL query or the service it proxies is too slow or unavailable. Check that your PostgreSQL (or backend for getIndicatorDataFromDb) is online and responsive.
- You can also increase your query timeout in your DB client or check for network issues.
- Optionally, add better fallback messages and check database health earlier in your handler to short-circuit if unavailable.

### General Test Reliability Fix

- Both issues may be due to flaky or unavailable services in CI. Ensure Redis and PostgreSQL services are healthy and properly linked.

**Summary of code change suggestions:**

- Use a safe Redis client getter as above.
- Guard tests and mutating Redis actions with isRedisAvailable().
- For database errors, ensure the DB connection pool is configured with higher timeouts if slow, and that the DB instance is running.
