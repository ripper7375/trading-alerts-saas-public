The failing job is caused by Redis connection errors (`[Redis] Invalidate pattern error: Error: Connection is closed.`) when running cache invalidation or test code that calls `invalidatePattern` and `clearAllCache`. This causes test failures due to unavailable cache and timeouts. The most relevant code is in [`lib/cache/redis.ts`](https://github.com/ripper7375/trading-alerts-saas-public/blob/875b4f7e77a0e50bcaf338a585191281a2064215/lib/cache/redis.ts#L110) and [`lib/cache/indicator-cache.ts`](https://github.com/ripper7375/trading-alerts-saas-public/blob/875b4f7e77a0e50bcaf338a585191281a2064215/lib/cache/indicator-cache.ts#L376):

**Solution**

1. **Ensure Redis is Connected Before Operations**

   Before running any Redis command (especially in `invalidatePattern`, `clearAllCache`, and test setup/teardown), check if Redis is available, and if not, either skip cache-related operations or use a fallback.

   ```typescript
   // Add at the start of invalidatePattern and similar functions
   import { isRedisAvailable } from './redis';

   export async function invalidatePattern(pattern: string): Promise<number> {
     if (!(await isRedisAvailable())) {
       console.warn('[Redis] Unavailable, skipping invalidatePattern.');
       return 0;
     }
     // ... rest of function
   }
   ```

2. **Handle Redis Unavailability Gracefully in Tests**

   Update integration tests to mock or skip cache invalidation if Redis is not up, to avoid job-breaking errors due to external dependencies.

3. **Optional: Add Test Redis in CI**

   If not already done, ensure the GitHub Actions workflow spins up a Redis instance using a `services:` block:

   ```yaml
   services:
     redis:
       image: 'redis'
       ports:
         - 6379:6379
   ```

**Summary of Code Changes**

- Check Redis availability before cache operations.
- Skip or warn when Redis is down rather than throw.
- Ensure CI provides Redis.
