- The import paths like `@/lib/api-clients` or `../utils/test-helpers` are incorrect, or
- The relevant files are missing from your repository, or
- Your test environment (e.g., Jest config, tsconfig, or build setup) does not resolve aliases or non-relative imports.

1. **Check that the modules exist:**
   - Verify that all files referenced at the top of your failing test files exist. For example, in [stack-b.test.ts](https://github.com/ripper7375/trading-alerts-saas-public/blob/6a796e05369a1ab621fd2ee6c92cbc923787ade4/frontend/__tests__/integration/stack-b.test.ts) and similar, check that
     - `@/lib/api-clients`
     - `../utils/test-helpers`
       exist in the correct locations.

2. **Fix path or module resolution:**
   - If you use `@/` as an alias, ensure your Jest configuration (`jest.config.js`) and TypeScript config (`tsconfig.json`) are set up to resolve `@/` to the correct base directory. For Jest, you likely need an entry like:

   ```js
   moduleNameMapper: {
     '^@/(.*)$': '<rootDir>/frontend/$1'
   }
   ```

   Adjust `<rootDir>/frontend/` according to your repo structure.

3. **Missing dependencies:**
   - If these files are supposed to be generated or come from another package, ensure the relevant build or setup scripts are being run before tests, and all dependencies are installed.
