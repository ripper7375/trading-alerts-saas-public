The failing job encountered two main issues:

### 1. Database Connection Errors

- Many errors are: `connect ECONNREFUSED 127.0.0.1:5432`
- This means tests expect a running PostgreSQL instance, but it's not available in CI.

**Solution:**  
Ensure the CI workflow starts PostgreSQL before running tests.  
In your workflow YAML file (.github/workflows/ci-nextjs-progressive.yml), add:

```yaml
services:
  postgres:
    image: postgres:13
    ports:
      - 5432:5432
    env:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: trading_alerts
    options: >-
      --health-cmd pg_isready
      --health-interval 10s
      --health-timeout 5s
      --health-retries 5
```

Make sure your application’s test config connects using these credentials.

---

### 2. Module Resolution Errors in Tests

- Example error:
  ```
  Could not locate module @/components/charts/indicator-overlay mapped as:
  ```
- Tests can’t resolve `@/components/charts/indicator-overlay`.

**Solution:**  
Ensure your `jest.config.js` (or `jest.config.ts`) maps `@` to the correct directory:

```js
module.exports = {
  // other config...
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/app/$1',
  },
};
```

Adjust `<rootDir>/app/$1` as needed to match your project structure.

---

### 3. Redis Connection Error

- e.g., `[Redis] Invalidate pattern error: Error: Connection is closed`
- Tests expect Redis and may fail if not running.

**Solution:**  
If tests require Redis, add a Redis service to workflow YAML:

```yaml
redis:
  image: redis:latest
  ports:
    - 6379:6379
```

If possible, mock Redis in tests to avoid needing an actual instance.
