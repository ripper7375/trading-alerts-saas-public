The failing job is a TypeScript compile error in `hooks/use-ohlcv-socket.ts` at line 76:

> `TS4111: Property 'NEXT_PUBLIC_MT5_WS_URL' comes from an index signature, so it must be accessed with ['NEXT_PUBLIC_MT5_WS_URL'].`

This happens when your TS config treats `process.env` as an index-signature type (common with stricter settings / newer TS), which disallows dot-access for specific env keys.

## Fix (recommended): use bracket notation

Update `hooks/use-ohlcv-socket.ts` to access the env var with `['...']`:

```ts
// hooks/use-ohlcv-socket.ts

useEffect(() => {
  const wsUrl =
    process.env['NEXT_PUBLIC_MT5_WS_URL'] ?? 'http://localhost:5001';

  const socket = io(wsUrl, {
    transports: ['websocket'],
    reconnectionAttempts: 5,
    reconnectionDelay: 2000,
  });

  // ...
}, [symbol, timeframe]);
```

That directly resolves `TS4111` and should allow the job to pass.

## Optional: make the type explicit (if you want stricter typing)

```ts
const wsUrl =
  (process.env['NEXT_PUBLIC_MT5_WS_URL'] as string | undefined) ??
  'http://localhost:5001';
```

But the simple bracket access is usually sufficient.
