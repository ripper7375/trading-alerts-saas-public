The job is failing due to **component test expectations no longer matching the current `TradingChart` implementation**. The failing suite is:

- `__tests__/components/charts/trading-chart.test.tsx`
  - “loading state › should show loading spinner initially”
  - “error handling › should show error message on fetch failure”
  - “error handling › should show error details”

## Root cause

Your tests assume `TradingChart` **fetches** `/api/indicators/...` and:

- shows **“Loading chart…”** while the fetch is pending
- shows **“Error loading chart”** plus an **error detail string** (e.g. “Symbol not found”) when `fetch` fails

But the `TradingChart` being imported in the test (`import { TradingChart } from '@/components/charts/trading-chart';`) now points to the Socket-based implementation in `components/charts/trading-chart.tsx`, which:

- uses `useOhlcvSocket(symbol, timeframe)` instead of `fetch`
- shows **“Connecting to live data…”** (not “Loading chart…”)
- renders error text from the socket hook’s `error`, not from a failed fetch response
- displays info text “Displaying live OHLCV candlestick data” (not the “only”/refresh-interval copy your tests expect)

So the fetch mocks and text matchers in the test will never line up with the rendered UI.
