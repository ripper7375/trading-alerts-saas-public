The failing job **65817990159** is breaking during the **Next.js build type-check step** (`pnpm run build`). The error is:

> `./hooks/use-ohlcv-socket.ts:76:19 Type error: Property 'NEXT_PUBLIC_MT5_WS_URL' comes from an index signature, so it must be accessed with ['NEXT_PUBLIC_MT5_WS_URL'].`

### Root cause

In `hooks/use-ohlcv-socket.ts`, the env var is accessed via dot notation:

- File: https://github.com/ripper7375/trading-alerts-saas-public/blob/d09f59ad41f5d801c5e38f4900dee0d4d2513c78/hooks/use-ohlcv-socket.ts#L74-L77

```ts
const wsUrl = process.env.NEXT_PUBLIC_MT5_WS_URL ?? 'http://localhost:5001';
```

With your current TypeScript/Next.js typings, `process.env` is treated as an index-signature type, so TypeScript requires bracket access for custom env keys.

### Fix (recommended)

Change the env access to bracket notation:

```ts
const wsUrl = process.env['NEXT_PUBLIC_MT5_WS_URL'] ?? 'http://localhost:5001';
```

So the updated block becomes:

```ts
useEffect(() => {
  const wsUrl =
    process.env['NEXT_PUBLIC_MT5_WS_URL'] ?? 'http://localhost:5001';

  const socket = io(wsUrl, {
    transports: ['websocket'],
    reconnectionAttempts: 5,
    reconnectionDelay: 2000,
  });

  // ...
}, [symbol, timeframe]);
```

This directly resolves the build/type-check failure.

### Optional improvement (stronger typing)

If you want to keep dot-notation, you can also add an env typing augmentation (e.g., in `env.d.ts` or `global.d.ts`) declaring `NEXT_PUBLIC_MT5_WS_URL`, but the simplest, lowest-risk change is the bracket notation above.

After committing this change, the workflow **Next.js CI (Progressive)** build step should pass for this error.
