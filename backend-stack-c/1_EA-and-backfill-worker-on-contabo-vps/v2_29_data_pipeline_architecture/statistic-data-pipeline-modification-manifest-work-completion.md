## 1. What was asked, and what it turned into

The screenshot's premise was that `Non-Recent-B` was missing fields the `.mq5`
should have been exporting. **It was not: that file's source has written
`[EDT CHANNEL]` since 2026-09-09, in the same commit (`e141f59b`) as Best_Fit_A.**
The two exports were produced by terminals running binaries older than the source —
Best_Fit_A's from the 2026-09-11 build, Non-Recent-B's from before that. This is
the stale-binary failure mode blueprint §13 item 1 already warns about, and it was
the first thing checked rather than the last.

Davin's own reasoning about Time-Decay Lambda was correct: it is a BestFit-family
concept (`InpTimeDecayLambda` genuinely does not exist in the other five), so its
absence from Non-Recent-B is right.

**But auditing the source to prove that turned up a live data-loss bug, and it was
the variant-flavoured header lines that caused it.** `parse_statistic_file()`
matches labels **literally** and stores NULL on a miss:

- `Observation Window (Bars)` (BestFit A/B, MostRecent) never matched the single
  rule written for `Observation Window (Box B Bars)` (CherryPick, NonRecent).
  **Three of seven centroids had been storing NULL for `window_bars`.**
- Best_Fit_A's `config_params` captured **3 keys**; Non-Recent-B's captured **4**.
  BestFit A/B were silently dropping `Regression Centroids` and
  `Visual CFL/EDT Window` from the blob `config_hash` is built from — so the
  "someone reconfigured this indicator" signal was blind to a centroid-count
  change on those two.
- All seven centroids had `window_start_ts`/`window_end_ts` NULL in every row ever
  written, though both are one array lookup away.

Every one of these was measured by running the real collector parser over the real
captured exports, not inferred from reading the code.

A second round, prompted by Davin pointing at the three remaining statistic-emitting
files, found one gap per file:

- `SingleBestResistanceLinev3` / `SingleBestSupportLinev3`: **13 populated columns,
  55 NULLs, and none of the 40 new ones.** Also `regression_angle` NULL in every
  row to date — they export `Raw Slope` but never an angle, and a slope alone is
  not comparable across instruments or timeframes.
- `SupportAndResistantAutoCalibration`: **dropped in full.** `sr_levels` was
  excluded from `STAT_SOURCES` on 2026-09-16, so not one field reached the
  database. Plus a latent defect — `Window Bars: 67 (Max Cap: 3000)` coerces to
  `None`, so that field would have been silently NULL for every row the moment the
  source was ever ingested.

## 3. Design decisions worth carrying forward

**The variant-flavoured header lines were left exactly as they are.** They are
meaningful to a human reading one file, and rewriting `Regression Centroids (Best
WLS CFL)` into a generic name would lose that. The canonical values are
**re-emitted** under names identical in every file, and `STAT_FIELDS` gained label
aliasing — a rule may carry a tuple of spellings, canonical first — so a terminal
still on an older binary keeps populating the legacy columns rather than going
dark the moment the collector updates.

**A field had to be non-derivable to earn a column.** RMSE was rejected
(`sqrt(MSE)`); crossing density was rejected. **Durbin-Watson** was the strongest
addition: it measures serial correlation in the residuals, so `<1` says a straight
line is the wrong _model_ for this stretch of price rather than merely a badly
fitted one. That is the diagnostic R² cannot give on trending data — and R² is
measured **negative** in the real captured exports here.

**Residuals are measured against `ExtBaseLine[]`/`ExtBestFL[]` directly**, never by
rebuilding the line equation. Those buffers _are_ the fitted value at each bar, so
there is no intercept convention to get wrong — the exported `Anchored Y-Int` is
the value at the **anchor**, not the regression's `c` at bar index 0, and
confusing the two shifts every residual by thousands of USD.

**They live in their own sections with their own `Sample (n)`.** These are measured
over the **drawn** span, which is not always the sample the certified `[MODEL A/B]`
blocks use. Appending them to those blocks would have made one `Sample (n)`
describe two different populations.

**Empty means not available; zero is a measurement.** For a centroid,
`Above UOEDT Count: 0` says price never left the channel. For a single line there
is no channel to leave, so a `0` there would make a support line look like a
perfectly contained channel to anything reading the table without knowing which
source each row came from. Every channel field on the line indicators is written
**empty**, and `test_extended_statistics.py` §5 asserts precisely that.

**The sections are emitted even when entirely empty.** A consumer that sees a
section _disappear_ cannot tell "not applicable to this indicator" from "this
terminal is on an older binary than I think". An empty field says which it is.
This is also why the centroid block's early-return guard was removed: it emitted a
truncated `[FIT WINDOW]` for the no-bars case, giving the file two possible shapes —
the exact property this pass exists to remove, and the contract test caught it.

**`sr_levels` was NOT reshaped into the regression-fit schema.** The 2026-09-16
note is right that it is a different kind of document: it records
Freedman-Diaconis calibration, not residuals against a fitted line. Padding it
with ~20 permanently-empty `[CHANNEL GEOMETRY]` and `[RESIDUAL DIAGNOSTICS]` fields
would have added noise, not data. Its own vocabulary is captured instead, through
section-scoped collector rules.

**`sr_1..sr_8` are deliberately not duplicated.** They already reach Postgres
through `market_data`'s 95 columns. What was being lost is the **provenance** — which
fractal sample, what dispersion, and above all **Optimal Step**, the bucket width
every one of those levels is derived from and which nothing downstream could
previously know.

**Only identifiers declared in all seven centroids are touched.** `g_stat_excluded`
(absent from CherryPick A/B and MostRecent), `g_stat_lambda` (absent from
CherryPick B and MostRecent) and `Inp*VisualLookback` (named `InpCFLVisualLookback`
in BestFit A/B, `InpEDTVisualLookback` in the other five) are all avoided. That
non-uniformity is what broke 5 of 7 compiles on 2026-09-18.

**The round trips are the ones that matter.** Three separate files were built from
real captured exports and pushed through the real parser: a centroid recovering
**40/40** uniform columns with values matching an independent recomputation; a
line indicator recovering 19 with every channel column NULL and none zero-filled;
and `sr_levels` recovering all 10 calibration values (`sr_q25=4342.18`,
`sr_optimal_step=16.96`, `sr_iqr=23.39`, `sr_dist_support_pts=1260`, …) with every
regression-fit column NULL.

**The SQLite migration was reproduced, not reasoned about.** A database built from
the _old_ schema goes 37 → 87 columns on `open_db()`, is idempotent on re-open, and
accepts a row using every new column. With `migrate_statistics_table()` neutered,
the same insert raises. That failure mode is worth the test: `stage_statistics()`
is wrapped best-effort so a statistics failure can never reject a price cycle, so
the exception would be swallowed and **the whole statistics lane would go silently
dark while every other part of the pipeline reported success.**

### 5.1 Four mistakes of my own, and what each one cost

**A verifier that agrees with you is worth less than one you have watched fail.**
Both mutation harnesses were run against the final code, and both restore
byte-exact by sha256 in a `finally` block.

1. **A `git stash` I intended as a no-op** silently stashed the Prisma edit, and I
   only noticed when `prisma migrate diff` reported an empty migration. Recovered
   with `git stash pop`.

2. **The generator emitted double commas** into the push worker's `STAT_COLUMNS`,
   a hard `SyntaxError` — **and my cross-layer check passed anyway**, because it
   scraped the list with a regex instead of importing the module. A regex does not
   care whether Python can parse what it matched. `test_statistics_schema_sync.py`
   now **imports** both modules, and its docstring records why.

3. **My own contract test caught two uniformity defects I had introduced** into the
   fractal file: a `Live Bar TS (UTC)` field with no collector rule (written and
   silently dropped — removed, since `live_bar_ts` already carries it), and a
   `Regression Angle` placed in `[PRICE CONTEXT]` where no other file has it
   (moved to the resolved-line block, where the centroids put it).

4. **The additive-only migration check failed on the word "dropped" in a prose
   comment.** The check scanned the whole file as if it were SQL. It now strips
   `--` comments first — a check a comment can trip is a check nobody will trust.

### 5.2 Two existing tests were flipped, and why that is not loosening them

`test_sr_levels_source.py` carried two guards on the 2026-09-16 exclusion, and
both failed. **That guard worked exactly as designed**, and its own message named
the condition for revisiting it: _"STAT_SOURCES and STAT_FIELDS should be revisited
together with it"_. Enrolment was conditional on clearing **both** stated reasons,
and both are now closed — its vocabulary has ten section-scoped rules, and the
closed `source` enum is widened to 11.

They were replaced with the new invariant rather than deleted, and the replacement
is **stricter**: the contract enum and `STAT_SOURCES` must now agree **exactly**,
because a source the collector stages but the contract omits is a latent outage for
the other ten, not just for itself. The ordering hazard the old test protected
against is unchanged and moved into the migration header.

## 6. Deployment Status & Execution Plan

**Nothing here has reached a database.** MQL5 cannot be compiled in this
environment, so **MetaEditor is still the first real test** — every check in §5 is
a stand-in for the parts of the compiler's job a text tool can do.

1. ⏳ **Recompile all 11 statistic-emitting indicators in MetaEditor.**
   Run `python verify_mq5_frozen_identifiers.py` first (expects 10/10 PASS; it
   does not cover `SupportAndResistantAutoCalibration`, whose change is four
   literal lines). The 7 centroids + fractal + both line indicators + the SR
   calibrator. ZigZag, OHLCV and Z-Score emit no statistics and are unaffected.

2. ⏳ **Apply `20260920000000_add_indicator_statistics_extended`** to production
   Postgres. Safe at any time and independent of the rebuild: 50 nullable
   `ADD COLUMN`s, no row rewritten. Run `prisma migrate status` first — this repo
   has four times found unrelated migrations riding along with `migrate deploy`.

3. ⏳ **Deploy `railway-gateway`.** It auto-deploys from `main`.

4. ⏳ **Deploy the collector + push worker to the VPS, then the `.ex5` binaries.**
   `migrate_statistics_table()` widens the existing `xauusd.db` on first start.

**⚠ ROLLOUT ORDER IS LOAD-BEARING, and more so than last time.** This release
widens a **closed** `source` enum and the statistics POST is **batched**. The
contract sets `additionalProperties: false` and the pipe sets
`forbidNonWhitelisted: true`, so a single element carrying `sr_levels` — or any new
field — against an un-migrated gateway **400s the whole request**, and the push
worker quarantines every snapshot in that batch to `rejected_statistics.jsonl`
**and stamps `synced_at`**. Those rows are recoverable only by hand via
`replay_quarantine.py`. The reverse order merely 5xxs and retries.

**⚠ The staleness check has an exception now.** A stale binary hides itself: rows
are created, cycles validate, and the new columns are simply NULL, because the
parser correctly reads _missing_ as NULL rather than 0 and nothing errors. Confirm
a **fresh** `_Statistic.txt` really contains `[RESIDUAL DIAGNOSTICS; CLOSE PRICE]`
before trusting a green cycle — that single line covers **10 of the 11** files.
The eleventh, `SR_Levels_*_Statistic.txt`, keeps its own shape by design: check it
for `Max Window Bars` instead, which only the rebuilt binary writes.

**Not verified, and flagged rather than skipped.** No `.ex5` has been built, so no
statistic file in the new format has ever been written by MetaTrader — every
number in §4 and §5 comes from real captured exports driven through real code,
with the new blocks synthesised from the emission sequence read **out of the `.mq5`
source**. No live MT5 → Postgres round trip. No disposable-Postgres rehearsal of
the migration (`prisma migrate diff` cross-check only); acceptable here because
every statement is a nullable `ADD COLUMN` touching no existing row.

**Out of scope, deliberately.** ZigZag, OHLCV and Z-Score emit no statistic file
and are untouched — they are fully reproducible from their timeseries. The
indicator-side defects flagged on 2026-09-16 in `SupportAndResistantAutoCalibration`
(3001-row export, unread `is_backfill` parameter, unreachable intra-bar trigger,
`sr_*` hardcoded to 2 decimals) are unrelated to statistics and remain open. The
look-ahead-bias question in
`HISTORICAL-VALUES-LOOK-AHEAD-BIAS-OPEN-ISSUE.md` is untouched: these are
point-in-time snapshots by construction, which is why capturing them matters, but
this pass does nothing about the ~3000 bars of already-stored history.
