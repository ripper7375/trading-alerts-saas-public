## 5. §6A — **code complete — pending deploy + verification**

Monthly payouts are **not live** until every condition below is true. I cannot see production env vars or deploys, so **none of these is marked done**.

### Go-live conditions (your checklist)

- [ ] **G1:** this branch's money-service changes are **deployed to money-service** on Railway (`money-service/railway.toml`), and its deploy log shows the new commit. Until then the old daily `0 2 * * *` payout keeps running.
- [ ] **G2:** `CRON_ENABLED=true` in money-service's **production** env (Railway → money-service → Variables). Otherwise every `@Cron` job, payout and approval alike, skips itself.
- [ ] **G3:** payouts not paused. `/admin/disbursement/settings` shows **"Payouts active"**, **and** `DISBURSEMENT_ENABLED` is not `'false'` on **Railway money-service** as well as on Vercel. The page only reflects the Vercel value (D-4).
- [ ] **G4:** `DISBURSEMENT_PROVIDER=WISE` on **Railway money-service** if real payouts are intended (`MOCK` only simulates). **Check Railway directly.** The settings page's provider card shows the **Vercel** value, which can differ (D-4).

### Post-deploy verification (§6A.1)

1. money-service startup/scheduler logs show `process-pending-disbursements` registered at `0 2 1 * *` and `approve-matured-commissions` at `0 2 * * *`.
2. `/admin/disbursement/settings` shows "Payout schedule: Monthly — 1st of each month, 02:00 UTC" and the correct next run date.
3. Over the following days, commissions older than the approval window move PENDING → APPROVED daily (an audit row `cron.commissions_auto_approved` appears each day, even with a count of 0), and **no new batch appears** in `/admin/disbursement/batches` until the 1st.
4. On the 1st: a batch appears, or `cron.disbursement_skipped` with a reason if G3 was deliberately off, and the 06:00 UTC monthly report reflects it.

**Cut-over note:** the next automated payout after deploy is the 1st of the following month. If you want one last daily-style run first, trigger `POST /v1/cron-trigger/process-pending-disbursements` **before** deploying money-service.
