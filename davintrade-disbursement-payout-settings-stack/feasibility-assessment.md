## 5. Risks

1. **Silent default fallback.** When a read fails, both readers return defaults (per spec). So a revoked grant, or a DB fault limited to `SystemConfig`, would quietly revert enforcement to today's behaviour. Mitigation: `console.error` / `logger.error` with a stable tag (`[disbursement-settings]`). Davin should search the logs for that tag after the first run (listed in the manifest).
2. **Batch splitting under Wise `MANUAL` funding (D2).** Every extra batch means one more manual funding step. This is inert at the default of 100.
3. **Cadence cut-over.** After deploy, the next automated payout is the 1st of the following month. §6A.1 documents the manual pre-deploy trigger option.
4. **Optimistic concurrency** uses the maximum `updatedAt` of the 4 rows, so it detects an edit to _any_ of the 4 keys. That is the intended granularity. A row created by `seed` (with no admin edit) also counts as a version, which is harmless.
5. **Working tree is dirty with unrelated changes** (Stack C/D data files, deleted docs, and others). Part 2 stages only the files it touches.
6. `frontend/` holds stale copies of the config route and constants. It is a separate stack under CLAUDE.md §5 and is **not touched**.

## 6. Spec errors and omissions (summary)

- The C14 "no readers" claim is wrong (3 admin readers, A1).
- The `PayoutCalculator` eligibility path is missing from C11/E8 (A2).
- Module registration covers only `DisbursementModule` (A3).
- The G3/G4 verification path cannot see money-service env vars (A4).
- L24 should be L1. F-next/F-next+1 are F83/F84. Line drift: resources `:383`, register hook `:44`.
- The xlsx "rows" are `No.` values, and the file is untracked.
- The scheduler spec has no existing metadata-reading style to follow.

**Feasible with adjustments A1–A7.** None of these change the architecture, the storage model, the decisions D1–D9, or the enforcement semantics. They extend the same pattern to call sites the spec missed and correct the verification guidance. **Stop-gate not triggered.** Proceeding to Part 2.
